# Чтение знаний

Пустой запрос или `{"path":"."}` возвращает к неизменному root, заданному хостом подключения.
По умолчанию это [Project MCP](../../project/env/index.ts); у адресного чата
это назначенная сущность. Корень нельзя менять параметром запроса.
Поле path выбирает адрес
из children предыдущего ответа. [Address](address/README.md) проверяет точное
присутствие адреса в публичной структуре того же каталога, который показывает Workbench.

У root указан `path: "."`; выбранный узел и его `children` содержат адреса
вида `./путь` от того же root подключения.
Общий вход Project сохраняет пути вроде `./storybook/package/build`; при root
`storybook/package` тот же переход имеет путь `./build`, а следующий —
`./build/descriptor`. Пустой запрос после любого перехода возвращает к исходному root.
Просмотр контекста страницы использует выбранный адрес страницы как свой root.
Разрешённые общие нормы адресного чата доступны через `children` с адресами
`./rules/<публичный адрес нормы>`; их потомки сохраняют тот же префикс. Нормы не
расширяют доступ к посторонним ветвям Project.

Для пакета [Server](../server/src/mcp-type.ts) читает сохранённый нормативный
отчёт применённой рабочей ревизии. Если применённой версии нет, используется последняя
рабочая, а при её отсутствии — готовая проверенная сборка. Неприменённый кандидат
не заменяет действующую версию. [Проверка Package](../../package/build/conformance/index.ts)
подтверждает тип при выполненных проверках без ошибок и одной применимой группе
Repo, Component, Container, Cluster или Domain.
TODO сохраняются в отчёте и не блокируют выбор предметного MCP. Отчёт связывается с владельцем,
сохранённой нормативной проверкой и выбранной ревизией. Обновление каталога,
исходников либо новая подготовка не отменяют подтверждение рабочей версии.
Отсутствие отчёта, ошибка его выполнения и неоднозначность остаются явными.
Если рабочая ревизия сменилась во время чтения, возвращается `stale-report`.

HTTP-вход вызывает соответствующий предметный MCP: [Repo](../../repo/env/index.ts),
[Component](../../component/env/index.ts), [Container](../../container/env/index.ts),
[Cluster](../../cluster/env/index.ts) или [Domain](../../domain/env/index.ts).
Эти входы формируют описание, переходы, схемы и сценарии из сохранённых сведений Package.
Общие читатели содержания и навигации принадлежат `package/mcp`; HTTP-вход выбирает
предметного владельца и добавляет результат проверки типа.
Без однозначного подтверждения ответ сохраняет общие сведения и переходы,
добавляя `type-unconfirmed` и причину. Чтение не запускает тесты или сборку.
Эта ветка не читает схемы и сценарии неподтверждённой сущности: отсутствие
готовой схемы не подменяет явный результат нормативной проверки ошибкой чтения.
Директории и входы сред сохраняют общее раскрытие без наследования типа пакета.

Назначение берётся из модульного TSDoc владельца, а при его отсутствии — из
непосредственного package.json. В списке детей используется краткое назначение
пакета из package.json либо первый абзац TSDoc директории. Категория сохраняет расположение детей;
[Children](navigation/README.md) раскрывает только один следующий уровень.
Частные src, contract и spec не становятся отдельными переходами.

Выбранный владелец дополнительно раскрывает доступные input, output и slots как JSON Schema.
TypeDoc строит их из разрешённых TypeScript-типов и описаний TSDoc в той же
сессии разбора, что формирует справочник для интерфейса. Поля, обязательность,
массивы, enum, union и ссылки рекурсивных типов сохраняют смысл контракта.
Свободный текст не превращается в выдуманные ограничения.

Scenarios сохраняет исходники bun:test. Чтение не исполняет код, не запускает
тесты или сборку и не раскрывает соседние ветви. У отсутствующего источника
нет поля; категория не заимствует контракт детей.

Пути исходных файлов и отпечатки каталога остаются внутри читателя.
Сменившийся после обнаружения контракт отклоняется до обновления каталога.
Общий вход среды доставляет предметный JSON без независимой копии его схемы.
[Полные отчёты запусков](../../specs/presentation/README.md) имеют отдельного владельца;
они не подменяют исходники в этом входе.

[Журнал вызовов](../server/requests/meta/notes/journal.md) принадлежит Server.
