# Управление Storybook через MCP

Возможности описаны в [MCP](../README.md); [HTTP-прокси](../proxy/spec/scenario.spec.ts) и [сервер](../spec/server.spec.ts) имеют исполняемые контракты.

## Интерфейс агента

Инструмент `storybook` читает корневой вход или выбранного владельца
по необязательному `path`; его ответ определяет [HTTP-вход MCP](../rest/README.md).
Управляющие инструменты подключены в [MCP-сервере](../src/server.ts),
а точные параметры заданы его [схемами](../src/schemas.ts).
Управляющие запросы содержат `schemaVersion`; навигационный вызов `storybook`
его не принимает. Схемы строгие и ограничивают объём входных данных.
Prompts отсутствуют. Инструменты не принимают произвольный JavaScript,
идентификаторы CDP, абсолютные координаты или путь для записи снимка.

## Lazy-исполнение всех запросов

Постоянный stdio-транспорт использует [Lazy MCP](../../../tech/mcp/lazy/index.ts).
Каждый запрос инструментов или ресурсов исполняется в отдельном Bun worker
через существующий [Worker](../../../tech/build/worker/index.ts).
Worker загружает стабильный [App factory entry](../../src/mcp.ts), который
передаёт публичный контроллер [MCP-владельцу](../index.ts) только по запросу.
Native MCP SDK проверяет актуальную схему и исполняет обработчик.
Чтение каталога tools/resources также получает текущие определения;
уведомления list-changed предлагают клиенту перечитать их после правок.

App, его контроллер, schemas и упаковка ответа не загружаются в постоянном
transport. Поэтому правка обработчика или его транзитивной зависимости
попадает в следующий запрос без перезапуска MCP. Изменение самого bootstrap
или transport-протокола требует нового подключения; этот малый слой отделён
от изменяемой реализации приложения.

Единственный HTTP daemon и browser lifecycle сохраняют состояние на диске и
в своём процессе. Fresh `ensure` работает и при отсутствии daemon; прежние
проверки владения и startup lease координируют параллельных клиентов.
Обычное завершение worker не останавливает запущенный detached daemon.

Отмена передаётся native SDK и контексту App. Фабрика сервера ожидает cleanup
своих запросов при закрытии; исполнитель ограничивает время завершения и
принудительно завершает только свою группу. Progress сохраняет порядок и
внешний MCP token. Результат, image и resource blobs проходят без повторной
предметной интерпретации. Временный worker не становится владельцем captures.

## Ресурсы

Read-only resources: `storybook://state`, `storybook://graph`, package/view/
capture templates. Это bounded derived projections canonical graph/sessions,
не отдельный MCP registry.

## Представления браузера

Каждая подтверждённая вкладка имеет opaque viewId, связанный с target и packageId.
Agent получает semantic state and capture metadata; port, PID, targetId, Chrome
index, master token и private artifact path не раскрываются. Несколько viewId
одного package допустимы. MCP не владеет target records или reconciliation,
а делегирует операции nested lifecycle owner. Смена origin сохраняет viewId,
смена пакета его изменяет. Новые targets создаются в background; OS focus,
`ai-macos`, `@meta/chrome` и browser CLI как runtime dependency запрещены.
Ensure, attach, search и `check(live:false)` не требуют доступного CDP.

## Адресные агенты

Подключение чата использует тот же lazy-транспорт с отдельной
[фабрикой](../src/chat.ts). Она регистрирует только `storybook`
и отправляет запрос на `/api/chat/mcp` с выданным grant. Управляющие инструменты
приложения в такой сессии не появляются; область доступа проверяет daemon.

HTTP-прокси предметного чтения остаётся владельцем доставки `{path}`.
Он является одной из операций внутри общей lazy-доставки, которая обслуживает
также запуск, состояние, сборку, представления, взаимодействие, capture и ресурсы.
