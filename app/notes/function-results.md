# Как показываются результаты серверной функции

Код вызова, входные данные, результат и пункты принадлежат одному выполненному
сценарию. Открытие и выбор варианта показывают итог проверки из отчёта
отображаемой ревизии. Изменённые props и «Запустить заново» требуют нового прогона. Обычные данные выводятся целиком в read-only редакторе JSON,
без обрезки строк, массивов и объектов. Помеченное руководство Archetypes
показывает структуру файлов и исходные примеры кода отдельными редакторами.
Ошибка обозначается отдельно от результата.

Варианты, категории и описания берутся из обычных describe, test и expect.
Автор не добавляет поля для App, браузерный шаблон или отдельную декларацию вызова.
Исполняемый пример — [сценарий readPackage](../../archetypes/package/spec/scenario.spec.ts).

## Подготовка

[Сборщик](../scenarios/src/function-preview.ts) распознаёт
именованный публичный импорт функции из index.ts описываемой сущности и прямые
вызовы внутри одного внешнего describe.each. Псевдоним импорта сохраняется в коде.
Модуль, экспорт и точные координаты отличают прикладной вызов от подготовки,
hooks и тестов. Несколько прямых обращений показываются в порядке выполнения.

Код для редактора составляется из публичного импорта и фактических аргументов.
В первой поддержанной форме аргументы представимы обычными JSON/TypeScript
литералами. Специальные аргументы не подменяются выдуманным кодом: такое
представление пока не подготавливается, полный отчёт инспектора сохраняется.
В результатах специальные значения остаются в исходном переносимом формате
инспектора, включая метки undefined, NaN и ссылок.
При восстановлении исходника вызова `undefined` печатается как TypeScript-литерал,
в том числе внутри объектов и массивов. Явное поле с `undefined` сохраняется
отдельно от отсутствующего поля. Технический отчёт продолжает хранить исходную метку.
Если распознанный сценарий не удаётся представить, сборка сообщает об этом
с указанием исходника; сценарий не исчезает из готовой ревизии молча.

Сборка сохраняет эти данные вместе с ревизией. Загрузчик функции содержит только
данные; literal import браузерного template используется лишь для компонента.
Исходники и исходы вызовов для валидации остаются в полном отчёте.

## Выполнение выбранного варианта

Host передаёт App функцию запуска. Она отправляет идентификаторы узла,
ревизии и варианта вместе с JSON-полями props серверу. Исполняемые значения
остаются в исходной таблице теста. Сервер проверяет принадлежность сессии
и возвращает сохранённый итог выбранной строки вместе с вложенными темами.
При необходимости нового прогона readScenario получает индекс выбранной строки;
соседние строки не регистрируются и не выполняют подготовку.

Компонентные варианты используют тот же запуск. Сервер возвращает фактические
props проверенного render и итог тестов. До успешного результата браузер не
монтирует фикстуру и не передаёт ей новые props. При возвращении к проверенному варианту прежний экземпляр сразу обновляется
в том же semantic Document. Во время явного повторного теста он сохраняется скрытым. При ошибке, отмене или отсутствии выполненных проверок
компонент не показывается; вместо него остаются вывод и диагностика запуска.

Новые запуски выполняются последовательно, одинаковые запросы разделяют один
прогон. При смене варианта или уходе читатель отсоединяется; поздний ответ
не применяется к новому выбору. Завершённые результаты, включая неудачные проверки,
сохраняются для повторного выбора. Явный повтор заменяет итог новым выполнением;
ошибка его запуска показывается отдельно.
[Принадлежность результатов ревизии и их актуальность](../scenarios/notes/build-cache.md)
определяются владельцем исполнения.
Полный отчёт сборки остаётся источником документации MCP; результаты ручных
запусков не перезаписывают его и исходную таблицу сценария.

Во время выполнения центральную область занимает текстовый редактор с живым
выводом stdout и stderr Bun. Сообщения приходят через тот же HTTP-запрос
в формате NDJSON: прогресс передаётся до готовности результата. Ожидание очереди,
подготовка и сбор результата имеют собственные подписи. После завершения
редактор вывода сменяется результатом функции; итоговые статусы берутся из отчёта Bun.
При закрытии потока или переключении варианта его вывод перестаёт обновлять App.
Живой журнал ограничен 256 Ки символов с явным сообщением об ограничении;
полный stdout/stderr остаётся в результате readScenario.

Внешний путь выбирает инструмент запуска или валидации. Он не становится
требованием к обычному сценарию функции или компонента.
