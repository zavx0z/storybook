# Общее пространство Storybook

[Browser](../../index.ts) владеет одной браузерной страницей канонического
сервера. Project, Repo, Package и вложенные предметы выбираются внутри этого
пространства. Страница, realm, Canvas и пользовательское состояние сохраняются
при обычном переходе. Готовые изменения принимает [HMR страницы](../../../../../tech/hmr/meta/notes/updates.md).

## Создание и выбор пространства

Первое открытие принимает уже аттестованную страницу этого сервера либо
создаёт одну фоновую страницу. Начальная миграция выбирает сфокусированное
или видимое пространство, затем записанное предпочтительное. После принятия
эта страница становится единственным владельцем для всех последующих адресов.
Общее имя страницы — `storybook:workspace` для всех пакетов и корня Project.
Идентичность предмета принадлежит bridge и native markers. Старое имя
`storybook:<packageId>` принимается только у bridge без `inPageNavigation`;
после записи общего имени native recovery не допускает возврат к имени пакета.

Открытие другого пакета вызывает `navigate` agent bridge с ожидаемым исходным
пакетом, точным назначением, маршрутом и необязательной ревизией. Browser
проверяет результат и сохранение `timeOrigin`. Legacy bridge устанавливается
одной native загрузкой той же страницы. Явный recover и перенос записанного
origin также проходят отдельные проверки владения и адреса.

Общий профиль Chrome и lock запуска принадлежат Chrome client. Приватный
state сервера содержит одну `workspace.json` и общий lock пространства;
пакеты не создают отдельные browser targets. Чтение inventory и status
не запускает браузер. Ошибка известного соединения остаётся ошибкой.
Остановка сервера не закрывает общий браузер и страницы пользователя.

Существующие дополнительные legacy-вкладки не закрываются и не становятся
параллельными рабочими представлениями. Чужой origin принимается лишь по
записанному владению того же browser instance. Совпадение имени пакета
не разрешает перенаправлять страницу другого сервера.

## Reservation и восстановление

Открытия разных предметов сериализуются одним workspace lock, включая
несколько экземпляров lifecycle. Reservation сохраняется до создания target.
Dispatch-aware client отмечает `createSent` синхронно перед отправкой native
команды. Сбой до отправки очищает только запись с явным `createSent:false`.
Ошибка после отправки без receipt остаётся indeterminate и запрещает второе
создание. Отсутствие receipt не доказывает отсутствие отправки.

Восстановление принимает только уникальный новый target на исходном reservation
URL. Аттестованный baseline peer допускает продолжение работы, сохраняя
неизвестную reservation без изменения: peer не считается её receipt.
Явный recover может повторить создание лишь после завершённого inventory
без страниц этого сервера. Сведения об отказе ограничены фактами reservation,
путями без query и тремя read-only observations с отдельным бюджетом.
Target IDs, порты и query tokens не публикуются.

Миграция читает не более 4096 старых `target-*.json`. Подтверждённые owned
записи и неотправленные reservations удаляются после записи workspace.
Неизвестные отправленные reservations сохраняются до подтверждённого
восстановления. Миграция записей не закрывает физические legacy-вкладки.

Stalled bridge записанного пространства восстанавливается только после
независимой проверки native markers, origin и записанного адреса. Перед native
navigation повторно проверяется тот же target и URL. Обычный open не
перезагружает зависшую страницу. Явный recover сохраняет маршрут, view,
variant и Inspector; сервер может выбрать другой preview pin через точную
`expectedRevision`.

## Выбранный адрес и права действий

`currentWorkspace` возвращает выбранный адрес и identity, включая
`followEnvironment`. Корень Project имеет `packageId:null` и пустой маршрут.
Готовый и показанный Project допускает capture page, canvas и node с
`packageId:null`, `revision:null` и настоящим digest графа. Package capture
по-прежнему требует свою ревизию. Владение проверяется до и после screenshot;
сменившаяся identity не сохраняется как снимок прежнего предмета.
`listViews` возвращает не более одного представления; запрос другого пакета
возвращает пустой список. Ни одна из этих операций не меняет адрес страницы.

ViewId связан с target, пакетом и логическим маршрутом. При переходе к другому
предмету предыдущий handle удаляется. Непосредственно перед inspect, interact,
capture, applyRevision и close проверяется актуальное владение; bridge также
получает ожидаемый исходный пакет. Старая ссылка не позволяет выполнить действие
над выбранным позднее предметом. Проверки адреса и native target остаются
внутри Browser и не раскрываются агенту.

При `applyRevision` Browser разрешает существующему `preview` перейти только
к запрошенной ревизии. Обычный адрес сохраняется без preview pin. Target,
origin, pathname, логический маршрут, view, variant, Inspector и realm остаются
прежними. После независимой проверки identity, адреса, результата применения
и консоли Browser обновляет внутренний адрес и запись пространства, сохраняя
ViewId. Возврат прежней ревизии после новой ошибки консоли проходит такую же
аттестацию и сохраняет согласованные адрес и запись. Другие операции сохраняют
обычную строгую проверку выбранного адреса.

Переход проверки другого предмета с `followEnvironment:true` требует включённого
режима следования до отправки и commit страницы. Выключение toggle отменяет
переход. Явное открытие адреса не зависит от режима следования.

## Исполняемые проверки

Сценарий и тесты проверяют одно пространство при переходах между пакетами и
Project, конкурентные opens разных предметов, сохранение realm, выбор
сфокусированной страницы, границу legacy upgrade, настоящую сериализацию identity AgentBridge, abort/timeout, безопасные
reservations и recover, недоступный inventory и отклонение устаревших handles.
Инвентарь и обычные переходы не закрывают legacy peers и страницы пользователя.
