# Журнал MCP-запросов

Общий журнал MCP хранит последние 20 запросов всех агентов: имя инструмента, параметры, время,
статус и публичный ответ. Полные тела, поместившиеся в recent cache, возвращаются
без усечения. Cache не заменяет предметную историю Session archive. Служебные секреты и
внутренние адреса проходят очистку на публичной границе MCP. Для
`storybook_capture` запись хранит метаданные и `captureId` без base64.

Источник записи задаётся подключением агента: `agentId` различает подключения,
`address` связывает локальное подключение с его Display. Имя команды и адрес
её цели не определяют принадлежность журналу. Вызов локального агента присутствует
и в общем журнале, и в локальном. Каждый локальный журнал независимо хранит
последние 20 записей. Адресные индексы ограничены 64 источниками по LRU: запись
или адресное чтение обновляет их использование. При переполнении самый давно
использованный адрес освобождается целиком. Пока адрес остаётся в cache,
активность соседей не меняет состав его 20 последних записей.
Общий и локальный индексы ссылаются на один canonical payload. Все тела вместе
занимают не более 32 МиБ в UTF-8; одинаковая запись в двух индексах считается
один раз. При давлении на этот бюджет более старые тела освобождаются целиком,
а диагностические сведения сохраняются. У такой записи `input` и `result` пусты
и присутствует явное `omitted: {reason: "payload-budget", inputBytes, resultBytes}`.
Размеры относятся к исходному содержимому. Oversized одиночная запись получает
ту же отметку; частичный JSON или усечённый source никогда не выдаются.
Обычные небольшие входы и результаты сохраняются без изменений.

Пустой фильтр не заменяется общим журналом; отсутствие локальных вызовов даёт пустой список.

Общий Window находится в HUD и открывается через Tab. При отсутствии сохранённых
настроек он закрыт. [Локальное окно MCP](../../../../web/page/shell/mcp-window/README.md)
находится в Display и показывает только вызовы его агента. Оно также самостоятельно
читает ответ текущего адреса, не добавляя такие чтения в журнал вызовов агента.
Видимость и геометрия глобального окна, положение его Tab и состояния окон
каждого локального адреса сохраняются независимо.

HTTP-приём записи журнала допускает до 8 МиБ в UTF-8 на запись, отдельно от
лимита 64 КиБ обычных управляющих команд. Размер проверяется и по заголовку,
и при чтении потока; превышение отклоняется целиком, без усечения ответа.

Статус сервера содержит requestJournal: состояния последних записей, размеры
входов и ответов в UTF-8 и последнюю ошибку приёма записи. Сводка сохраняет исходные размеры и отметку omitted, не включает
содержимого ответов и доступна независимо от работоспособности окна журнала.

При одинаковом `startedAt` более поздний новый вызов показывается первым.
Переход уже записанного вызова из running в success/failed сохраняет его
первоначальное место среди вызовов с тем же временем. `residency()` раскрывает
только количество адресов, canonical records и общий размер удерживаемых тел.
