# Одна среда страницы и её представления

Одна опубликованная версия интерфейса Storybook используется во всех вкладках;
ревизия пакета не владеет общей оболочкой.

Среду создаёт [оболочка](../../shell/index.ts), её состав задаёт [приложение](../../shell/src/application.tsx). [Динамическое обновление](../../../../../tech/hmr/meta/notes/updates.md) определяет передачу владения новой реализации.

## Root, Display и HUD

Страница владеет ровно одним `@zavx0z/immersive-browser` Root и передаёт Browser
один native Canvas. Browser владеет semantic Document, Space, ViewPoint, циклом
кадров и вводом. Иерархия пакетов Project изображается сверху вниз без сворачивания.
Из каталога в граф попадают только узлы `kind === "package"`; общий корень Project
сохраняет главную страницу. Директории, публичные входы и недоступные пакеты не получают
отдельных узлов. Связь проходит к ближайшему пакетному предку через пропущенные
директории. Внутренние маршруты открываются в Display своего пакета.
Каждый пакет имеет настоящий Display слева от подписи; его существующий Workbench
сохраняет состав. Все поверхности являются соседями в одном Space.

Обычный и пространственный режимы используют один `StorybookDisplay` с прежней
flex-раскладкой, без отдельной рамки, фона и промежуточного контейнера Workbench.
CSS viewport каждого Display соответствует размеру окна и обновляется при resize.
Физическая миниатюра вписывается в место 20 × 12,5 мм с теми же пропорциями.
Физический размер маленькой поверхности отделён от CSS viewport.
Приближение камеры делает содержимое читаемым без перестройки его раскладки.
Подписи и связи используют общий SpatialGraph, координаты вычисляет Hierarchy Layout.
Камера не запускает повторную раскладку графа.

Содержимое загружается при выборе или приближении. Page удерживает ограниченное
число предметных исполнений (`maxWarmSubjects`, по умолчанию 6); фокус удерживает
исполнение до завершения ввода. Вытеснение освобождает UI и frontend-подписки,
сохраняя узел графа, настройки Inspector и предметную историю. Произвольное
локальное состояние сценария после полного вытеснения не сериализуется автоматически.
Выбранный адрес и Inspector принадлежат своему представлению; фоновые загрузки
и обновления соседних предметов не записывают browser History.
HUD содержит перетаскиваемый Tab управления ViewPoint: приближение, отдаление,
заморозку жестов и вписывание. [Minimap](../../shell/minimap/index.tsx)
показывает в HUD тот же каталог через общий UI `Window`; его `WindowControl`
находится в Tab. Окно MCP использует ту же оболочку в Display и управляющую
кнопку в строке состояния. Структурные обзоры и
сценарии используют этот Experience; они не создают второй Root или semantic
Document. Host default font загружается из exact
`@zavx0z/immersive-engine/fonts/inter-regular.ttf` через публичный export.
В compiled TSX свободное имя `document` связано Template с semantic Document
компонента, в том числе после `await`. Native document и одноимённые локальные
переменные его не подменяют. Внутренний контроллер проверяет Document перед
использованием его API.

При самостоятельном использовании Shell без графа служебный Display занимает
viewport страницы; preview находится внутри его раскладки. Для размеров `W × H`
физические атрибуты служебной поверхности равны `W × 25.4 / 96` и `H × 25.4 / 96` мм, CSS viewport —
`round(W) × round(H)` px, scale — `1`. Resize обновляет поверхность и ViewPoint
на тех же semantic nodes. Фиксированные размеры, PPI устройства и уменьшение
шрифта для подгонки не используются. В пространственном режиме служебная
поверхность скрыта, а экземпляры того же Display расположены у пакетов с
физическими габаритами миниатюр, описанными выше. Авторские характеристики физического
дисплея в отдельном сценарии сохраняются.
Для двумерной среды ViewPoint смотрит перпендикулярно Display; Display и HUD
находятся строго ближе дальней плоскости. Кнопка «Вписать» в графе показывает всю иерархию; выбор подписи приближает
камеру к Display предмета. В самостоятельном Shell команда повторяет подгонку
даже без изменения viewport либо возвращает авторский обзор пространственного примера. Заморозка меняет только controls общего ViewPoint: явные
команды масштаба и вписывания остаются доступны. Обновление размеров сохраняет DOM
identity, фокус и состояние компонентов; прокрутка ограничивается новым
viewport. Отдельные native страницы имеют собственные Experience; Display
сущностей внутри одной страницы используют общий Document, Canvas, Space и ввод.

## Композиция приложения и общий ввод

Страница запускает один `StorybookApp` через публичный
`@zavx0z/immersive-browser.createRoot`. App объявляет свой Space, ViewPoint, Display и HUD
в TSX; Browser не создаёт второй semantic каркас. Component владеет App,
его refs и cleanup. После `render` оболочка ожидает готовность приложения через
`whenReady()`; представленный кадр проверяется перед применением ревизии.

MCP pointer и wheel actions сначала преобразуют точку semantic target через
`getProjection(owner).projectPoint` в native client coordinates, затем
вызывают общий `root.input`. Они не вызывают input выбранной проекции
напрямую и не обходят hit/occlusion/capture. Для Space gestures используется
тот же input. Drag может пересечь границу Display/HUD; capture сохраняется.

## Исполнение структурных сценариев

Исполнение примеров принадлежит существующему структурному механизму сценариев.
Пакет не объявляет runtime adapter, загрузчики вариантов, presentation contract
или custom Inspector widgets. Оболочка владеет встроенными секциями Inspector;
Browser предоставляет один Document и Space без второго lifecycle.

## Последовательное освобождение

Создание и освобождение структурного сценария последовательны. Pending
исполнение получает AbortSignal; поздняя работа не заменяет текущий обзор.

Положение HUD Tab (сторона и доля края), заморозка и обзор Workbench сохраняются
в `localStorage` текущего origin. Новая сессия восстанавливает камеру после первого
расчёта размеров Display. Параметры того же ViewPoint, временно заданные пространственным примером,
не перезаписывают сохранённый обзор Workbench. Дополнительного ViewPoint нет. «Вписать» сохраняет новый обзор. В графе resize
обновляет CSS viewport и пропорции миниатюр без замены Display или Workbench; самостоятельный
Shell продолжает подгонять служебную поверхность к viewport. Повреждённое или недоступное хранилище не мешает запуску.
