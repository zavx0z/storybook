# Одна среда страницы и её представления

Опубликованная версия интерфейса Storybook применяется к общему workspace;
ревизия пакета не владеет общей оболочкой.

Один workspace браузера показывает адрес выбранной сущности. Переход к пакету
или корневому обзору проходит через Page в том же Experience. Bridge доступен и
на корневом обзоре: package identity и revision равны `null`, модель выбора отсутствует.
Имя native workspace — `storybook:workspace`; текущий адрес не создаёт отдельную вкладку пакета.

Среду создаёт [оболочка](../../shell/index.ts), её состав задаёт [приложение](../../shell/src/application.tsx). [Динамическое обновление](../../../../../tech/hmr/meta/notes/updates.md) определяет передачу владения новой реализации.

## Root, Display и HUD

Страница владеет ровно одним `@zavx0z/immersive-browser` Root и передаёт Browser
один native Canvas. Browser владеет semantic Document, Space, ViewPoint, циклом
кадров и вводом. Storybook передаёт каноническую иерархию Project → Repo → Package,
подписи, подготовленное содержимое и обработчики перехода по адресу.

`@zavx0z/immersive-nodes/spatial/tree` владеет представлением: независимыми Display,
Frame, объёмами, полом, видимостью и навигацией. Числовая раскладка находится в
отдельном `@zavx0z/immersive-nodes-layout-prism-tree`. Каждый предмет показан один раз;
его прозрачный Display занят одним Frame без второго внешнего заголовка.
Промежуточные директории и точки входа остаются содержимым пакета.

Уровни иерархии занимают параллельные XY-плоскости, но не образуют общей матрицы.
Каждый родитель упаковывает области своих дочерних поддеревьев вокруг собственного
центра. Единственный ребёнок продолжает этот центр вниз; завершение соседних ветвей
не стягивает продолжающуюся ветвь к центру сцены. Каждый прямоугольник, включая
листья, вытянут вниз на одинаковую постоянную глубину. От нижнего торца тела
отходят полупрозрачные объёмы к следующему уровню. Семейства различаются цветом;
CSS-переменные общих компонентов управляют материалом и прозрачностью.
Ветви слабее контуров тел. Все уровни разделяет одинаковый увеличенный шаг;
размах веера не меняет расстояние, глубину тел или локальные XY-центры.

Размеры Display принимаются при конфигурации дерева и сохраняются при жестах
и resize. Общий обзор показывает дерево под углом. Явный выбор вписывает выбранный
Display сверху; fly-навигация позволяет пройти сквозь его уровень к детям.
Сохранённая плоская поза не переносится на новую раскладку; её версия — `prism-tree/3`.

Immersive выбирает видимый набор через пространственный индекс: до 256 Display,
включая ограниченный набор активного содержимого, и до 6000 объёмов. При отдалении
остаётся общая геометрия тел. Стабильный ViewPoint не повторяет выборку;
запас вокруг viewport и пороги размеров уменьшают смену состава при малых жестах.
Подготовленное содержимое передаётся через обычную композицию Component в том же
Document. Дополнительного ComponentRoot на пакет нет.

Page загружает содержимое при переходе на другой адрес. Фокусировка Display,
pan, zoom, fit, представление кадра и idle меняют обзор готовой геометрии и видимость
содержимого посещённых пакетов. Page не подписывается на demand пространственного дерева.
Повтор текущего адреса сохраняет controller и содержимое; проверка выполняется в
очереди после предыдущего перехода. Первоначальная загрузка, HMR и переподключение
сохраняют свои явные lifecycle paths.

Page удерживает ограниченное число уже посещённых исполнений пакетов
(`maxWarmSubjects`, по умолчанию 6, максимум 32). Выбранный пакет и текущий ввод
защищены от вытеснения. Явный переход выбирает Frame и приближает ViewPoint.
Проверки владения запрещают callbacks позднего неподтверждённого scope менять
выбранное представление. Зарегистрированные посещённые scopes сохраняют свои callbacks
до освобождения. HMR использует проверенный host и существующий бюджет исполнения.
Вытеснение освобождает UI и frontend-подписки, сохраняя Inspector и предметную историю;
произвольное локальное состояние сценария после полного освобождения не сериализуется.

Каталог текущего Project — конечный рабочий набор для построения геометрии и индексов.
Отображение ограничено бюджетами, но этот источник ещё не является постраничным
хранилищем миллиардов сущностей: большие источники должны предоставлять рабочие
области, а не полный граф одним снимком.

Геометрический пол находится в плоскости XY на Z=0; сетка в текущем представлении
выключена. Нижний торец
первого завершившегося уровня дерева опирается на пол; более глубокие уровни
продолжаются ниже пола.
Уровень пола неподвижен в принятой раскладке. Скрытая сетка не влияет на диапазон
видимости; при необходимости её предоставляет общий компонент `Space/Grid`.

Один общий белый источник света в Space освещает прозрачные тела. Их
`GlassMaterial` фильтрует проходящий свет и отражает освещение; параметры и
оптическое приближение принадлежат Engine/WebGPU, а не Page.

HUD содержит перетаскиваемый Tab управления ViewPoint: приближение, отдаление,
заморозку жестов и вписывание. [Minimap](../../shell/minimap/index.tsx)
показывает в HUD тот же каталог через общий UI `Window`; его `WindowControl`
находится в Tab. Окно MCP использует ту же оболочку в Display и управляющую
кнопку в строке состояния. Структурные обзоры и
сценарии используют этот Experience; они не создают второй Root или semantic
Document. Host default font загружается из exact
`@zavx0z/immersive-engine/fonts/inter-regular.ttf` через публичный export.
В compiled TSX свободное имя `document` связано Template с semantic Document
компонента, в том числе после `await`. Native document и одноимённые локальные
переменные его не подменяют. Внутренний контроллер проверяет Document перед
использованием его API.

Рядом с «Вписать» находится «Следовать». По умолчанию режим выключен; Shell
сохраняет его состояние для HMR и переподключения. Page принимает только начало
работы из environment activity с адресом назначенного предмета. Повтор одного
события и повтор текущего адреса не загружают содержимое. Старое начало, пришедшее
после нового через другой socket, не возвращает workspace к прежней сущности.
Инспекция и наблюдение не порождают следование. Выключение режима или ручной
переход отменяют ожидающую навигацию; поздний transport/import не фиксирует адрес
и не удерживает очередь ручного перехода. Камера сохраняет собственные команды.

При самостоятельном использовании Shell без графа служебный Display занимает
viewport страницы; preview находится внутри его раскладки. Для размеров `W × H`
физические атрибуты служебной поверхности равны `W × 25.4 / 96` и `H × 25.4 / 96` мм, CSS viewport —
`round(W) × round(H)` px, scale — `1`. Resize обновляет поверхность и ViewPoint
на тех же semantic nodes. Фиксированные размеры, PPI устройства и уменьшение
шрифта для подгонки не используются. В пространственном режиме служебная
поверхность скрыта, а независимыми Display сущностей владеет Immersive SpatialTree.
Внутреннее содержимое каждого Frame использует его поверхность. Авторские характеристики физического
дисплея в отдельном сценарии сохраняются.
Для двумерной среды ViewPoint смотрит перпендикулярно Display; Display и HUD
находятся строго ближе дальней плоскости. Кнопка «Вписать» в графе показывает всю иерархию; выбор подписи приближает
ViewPoint к Display предмета. В самостоятельном Shell команда повторяет подгонку
даже без изменения viewport либо возвращает авторский обзор пространственного примера. Заморозка меняет только controls общего ViewPoint: явные
команды масштаба и вписывания остаются доступны. Обновление размеров сохраняет DOM
identity, фокус и состояние компонентов; прокрутка ограничивается новым
viewport. Отдельные native страницы имеют собственные Experience; Display
сущностей внутри одной страницы используют общий Document, Canvas, Space и ввод.

## Композиция приложения и общий ввод

Страница запускает один `StorybookApp` через публичный
`@zavx0z/immersive-browser.createRoot`. App объявляет свой Space, ViewPoint, Display и HUD
в TSX; Browser не создаёт второй semantic каркас. Component владеет App,
его refs и cleanup. После `render` оболочка ожидает готовность приложения через
`whenReady()`; представленный кадр проверяется перед применением ревизии.

MCP pointer и wheel actions сначала преобразуют точку semantic target через
`getProjection(owner).projectPoint` в native client coordinates, затем
вызывают общий `root.input`. Они не вызывают input выбранной проекции
напрямую и не обходят hit/occlusion/capture. Для Space gestures используется
тот же input. Drag может пересечь границу Display/HUD; capture сохраняется.

## Исполнение структурных сценариев

Исполнение примеров принадлежит существующему структурному механизму сценариев.
Пакет не объявляет runtime adapter, загрузчики вариантов, presentation contract
или custom Inspector widgets. Оболочка владеет встроенными секциями Inspector;
Browser предоставляет один Document и Space без второго lifecycle.

## Последовательное освобождение

Создание и освобождение структурного сценария последовательны. Pending
исполнение получает AbortSignal; поздняя работа не заменяет текущий обзор.

Положение HUD Tab (сторона и доля края), заморозка и обзор Workbench сохраняются
в `localStorage` текущего origin. Новая сессия восстанавливает ViewPoint после первого
расчёта размеров Display. Параметры того же ViewPoint, временно заданные пространственным примером,
не перезаписывают сохранённый обзор Workbench. Дополнительного ViewPoint нет. «Вписать» сохраняет новый обзор. В графе resize
сохраняет принятую геометрию дерева и обновляет область видимости; самостоятельный
Shell продолжает подгонять служебную поверхность к viewport. Повреждённое или недоступное хранилище не мешает запуску.
