# Границы миграции HMR

Действующее поведение описано у [HMR](../../../../../tech/hmr/meta/notes/updates.md).
Структурные нормы принадлежат [Архетипам](../../../../../package/meta/notes/requirements-map.md).
Эта заметка сохраняет границы интеграции и условия, которые ещё не выражены
самостоятельными владельцами legacy runtime.

## Владельцы исполнения

| Ответственность | Владелец |
| --- | --- |
| Замена scope, последовательное освобождение, rollback | [Page](../../../../../tech/hmr/page/index.ts) |
| Проверка кадра, identity и ошибок перед commit | [Activation](../../../../../package/activation/index.ts) |
| Reconnect, listeners и отмена соединения | [Connection](../../../../../tech/hmr/connection/index.ts) |
| Разрешение адреса, подготовка цели и композиция страницы | [page-entry](../../index.ts) и [package-page-target](../../../../server/src/package-page-target.ts) |
| Отображение документации, Inspector и сценариев | [package-entry](../../package/index.ts) |
| Выбор согласованной среды и передача Canvas при смене платформы | [shared-host](../../../protocol/src/shared-host.ts) и [page-entry](../../index.ts) |
| Поколения, activation leases, active/lastWorking и receipt | [StorybookPackageSession](../../../../../package/session/index.ts) |
| Проверки исходников и компиляция | [Build](../../../build/meta/notes/compilation.md) |

Технический Domain `tech/hmr` собирает публичные API Page и Connection.
Компоненты сохраняют identities `@zavx0z/storybook-tech-hmr-page` и `@zavx0z/storybook-tech-hmr-connection`, а собственные
типы публикуют через пространства StorybookTechHmrPage и StorybookTechHmrConnection. Page получает
release/restore от реального исполнителя. Activation остаётся в предметной области
`package/activation` и получает inspect/commit от владельцев браузера и сессии.
Компоненты не импортируют фасад родителя и private runtime Storybook.

Контроллер страницы связывает навигацию и platform handoff с Page. Отдельный
исторический package entry ещё используется вариантом builder без общей
платформы и непосредственными тестами package runtime. Он также использует
Page для замены и отката. Удалить этот вход можно только после миграции этих
потребителей; его ограничение смены платформы не означает разрешение reload.

## Сохранение состояния

Кнопка Minimap и управляющий вызов `app` публикуют один Web-выпуск для всех
открытых страниц. Корневая страница и страницы пакетов принимают один проверенный
`shared.updated.host`; reconnect запрашивает текущий выпуск. Выпуск платформы
и пересборка пакетов для этой операции не требуются. На текущем этапе сохранено
перемонтирование App с восстановлением состояния оболочки, разрешённое пользователем.

Для обновления сохраняются native Document, Canvas и browser timeOrigin.
Browser Root и semantic Document передаются новой оболочке при совпадении
платформы и упорядоченного списка author stylesheet specifiers по
[условию передачи](../../index.ts). Изменение содержимого CSS при прежнем
списке specifiers само по себе не меняет это условие. Смена платформы или списка
освобождает прежний Root и создаёт согласованную среду на том же Canvas;
semantic Document при этом заменяется. Передача Root не означает сохранения
внутреннего состояния заново смонтированных компонентов.

Маршрут, Inspector, вариант сценария, поиск, прокрутка и настройки оболочки
переносятся по явным capture/restore контрактам. Состояние произвольного
пользовательского сценария не объявляется сохранённым без такого контракта.
Навигация меняет URL через history; обновление остаётся на текущем адресе.

## Подготовка при навигации

Доступная готовая ревизия открывается без перепроверки редактируемых исходников.
При её отсутствии, включая legacy без platform identity, выбирается обычная
подготовка выбранного пакета: проверки, очередь и компиляция. Подписки и файловые
изменения сами ничего не запускают. Preview новой сборки не создаёт.

Первый navigation-candidate запрашивает подтверждение после установки страницы.
Сервер независимо проверяет точную ревизию и кадр, затем закрепляет её через
Activation и session lease. Браузер не передаёт произвольную revision или working.
Доступная рабочая версия обновляется только явным live-check.

## Оставшиеся границы

- Перенос состояния произвольного сценария требует контракта самого сценария.
- Навигация сейчас выполняет выбранные переходы последовательно. Отдельное
  изменение политики быстрых переходов требует сценария отмены устаревшего
  ожидания; отмена одной страницы не должна отменять общую полезную сборку.
- Payload исполнения и graph revision пока принадлежат существующим runtime
  и sessions. Их дальнейшее выделение требует миграции build-generated imports
  и публичных контрактов реальных владельцев, а не общего пакета types.
- Подготовка повреждённого receipt не может отменять strict или подставлять другую
  платформу. Отсутствующий формат и нарушение целостности — разные случаи.

## Исполняемые свидетельства

У каждого HMR-компонента есть непосредственный scenario.spec, отрицательные
случаи и проверки lifecycle. Прежний тест Runtime integration (`package/test/package-entry.test.ts`)
отсутствует в текущей структуре. Сохранение Canvas, Root, rollback, Inspector
и reconnect требует подтверждения актуальными интеграционными проверками. [Server integration](../../../../server/test/checked-publication.test.ts)
проверяет независимую инспекцию и подтверждение exact lease.
[Навигация](../../../../server/test/server.test.ts) проверяет подготовку отсутствующей
сборки, повторное использование и сохранение рабочей версии при редактировании.

Эти проверки не заменяют live-подтверждение actual package/route/revision,
ready/presented, timeOrigin и ошибок console в существующих вкладках. Публикация
на сервере сама по себе не является свидетельством применения каждой страницей.
