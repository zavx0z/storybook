# Просмотр сценариев

Страница Package связывает код использования сущности, данные выбранного варианта
и его пункты. [Читатель сценария](../../../../../specs/scenarios/reader/README.md) сохраняет полный отчёт;
фикстура компонента принадлежит самому компоненту, а загрузка подготовленного
представления — сборке Storybook. Archetypes извлекает из отчёта
[руководство по написанию](../../../../../specs/scenarios/reader/README.md).

Вверху Inspector находится один Editor с подсветкой TypeScript. Под ним
варианты образуют аккордеон: раскрытие показывает сохранённый итог проверки
отображаемой ревизии. Компонент появляется после успешной проверки с её props.
«Запустить заново» явно выполняет новый тест.
Во время проверки или при ошибке общий экземпляр скрыт. В Display остаётся только результат, расположенный по центру
по фактическим локальным границам Display, с сохранением авторских размеров
и absolute-позиционирования самого компонента. Host читает `getLayoutRect`,
который не включает CSS transforms и проекцию ViewPoint, и задаёт конечное
смещение stage. Смещение не накапливается между кадрами; совпавшее положение
не вызывает повторного render.

Для серверной функции Inspector показывает её вызовы с фактическими аргументами.
Выбор варианта использует отчёт той же ревизии. Изменённые параметры и явный
повторный запуск требуют нового теста.
До завершения показываются этап запуска и живой текстовый вывод Bun;
затем — результат проверок
и полные данные вызовов в редакторе JSON. Результат руководства Archetypes
показывается как роли файлов, исходники в редакторах кода и состояния правил.
Возврат к уже проверенному варианту сразу показывает сохранённый результат. Код серверной функции остаётся на сервере.
При быстром переключении ответ предыдущего запуска не заменяет текущий результат.

Host монтирует preview в свой semantic Document и освобождает его при уходе
со страницы сценария. Переключение варианта сохраняет экземпляр компонента.

[Исполняемые примеры](model/spec/scenario.spec.ts) раскрывают публичный выбор варианта,
снимки компонента и функции, уведомление подписчика и отписку.
