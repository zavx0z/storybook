# Правила структуры проектов

Этот пакет описывает общие правила, по которым Storybook читает проекты и
пакеты. Правила применяются и к визуальным, и к невизуальным пакетам.

## Явный состав проектов

Пользователь добавляет и удаляет проекты через интерфейс Storybook или MCP.
Постоянная конфигурация находится в `~/.storybook/projects.json` и содержит
только JSON-массив абсолютных путей к выбранным каталогам:

```json
[
  "/path/to/project",
  "/path/to/independent-package"
]
```

Порядок путей задаёт порядок корней. Пустой массив означает пустой каталог.
Storybook не восстанавливает состав из списка соседних репозиториев, PID,
старых запусков или кэша сборки. Повторное добавление того же каталога не
создаёт дубль. Удаление из списка не удаляет файлы проекта.

Конфигурация не содержит имён, идентификаторов, категорий и копий metadata.
Эти сведения читаются из выбранного проекта. Если удаляется вложенная ветвь
старой композиции, оставшиеся ветви сохраняются своими путями, без списка
скрытых идентификаторов и без изменения декларации владельца.

## Человекопонятное название

Корень проекта и каждый самостоятельный пакет объявляют непустой `label`
в своём `package.json`:

```json
{
  "name": "@scope/parser",
  "label": "Разбор выражений"
}
```

`name` — техническая идентичность для зависимостей и импортов. `label` —
название для человека. Изменение `label` не меняет `name` и маршруты.
Storybook читает `label` при открытии и обновлении проекта; UI и MCP используют
одно название из общего каталога. Имя не сохраняется в пользовательской
конфигурации и не выводится из имени удалённого ранее проекта.

## Структура и манифест

Структура — сведения из устройства проекта и его package.json. Манифест —
явное описание содержимого в .storybook. Оба подхода передают один каталог
в UI и MCP.

Состав внутренних пакетов структурного проекта задаётся `package.json#workspaces`.
Точные каталоги, `packages/*`, `packages/**` и исключения `!packages/excluded/**`
раскрываются встроенным Bun.Glob. Порядок шаблонов сохраняется, внутри шаблона
пакеты упорядочены по пути; пересечения не создают повторных пакетов.
Каталоги без package.json не становятся пакетами. node_modules и .git
не входят в состав. Пути остаются внутри проекта; symlink-каталоги отклоняются.

Каждый найденный пакет виден и доступен для выбора, даже когда у него нет
`.storybook/manifest.json`. Имя и название читаются из package.json; при
отсутствии манифеста README.md пакета служит его описанием, если существует.
Наличие preview, TSX или графического runtime не является требованием.
Манифест пакета, если он существует, добавляет каталог, сценарии, ресурсы
и runtime. Некорректный существующий манифест даёт локальную диагностику;
его отсутствие ошибкой не является.

Проект с workspaces не повторяет состав в manifest.packages. Для прежнего
манифестного подхода без workspaces сохраняется явный список packages.
Одновременное задание обоих источников отклоняется. Корневой манифест может
сохранять id и readme проекта. Без корневого манифеста каталог с workspaces
распознаётся как проект с нормализованным id по имени каталога; без workspaces — как отдельный
пакет. Явный kind: package сохраняет пакетный корень, в том числе собственную
документацию Storybook; его workspaces не меняют тип корня неявно.

Изменения состава и появление или удаление манифеста отслеживаются через
общий watcher. Идентичность существующего пакета сохраняется. Пакет владеет
своими исходниками, документацией, сценариями и проверками. Названия всех
корней и пакетов обязательны в package.json#label; label в manifest запрещён.
