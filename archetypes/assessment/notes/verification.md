# Что подтверждает оценка стандарта

[readAssessment](../index.ts) последовательно выполняет нормативные сценарии
Package и пробу Repo; для некорневого пакета — пробы Domain и Component.
Класс выбирается по результатам assertions, а не по полю манифеста.
Отрицательная проба неприменимого класса сохраняется в отчёте, но не становится
нарушением выбранного класса. Domain и Component взаимоисключающие.

Общий итог учитывает все применимые suites. Собственный сценарий обязателен
для Component. Для Domain общие проверки используют структуру и exports;
собственный spec не требуется. Имеющийся предметный сценарий Domain исполняется,
его ошибки сохраняются; два неоднозначных источника не считаются отсутствием. `classification` публикуется только при `status: passed`.
`failed` означает провал применимого требования, `incomplete` — неполноту проверки;
оба состояния оставляют классификацию неподтверждённой. Документированный
условный пропуск выражает неприменимость; TODO не считается прохождением.
Техническое исключение, отмена или отсутствие завершающего отчёта пробрасываются.

Project проверяется отдельно как набор ссылок на Repo. Исполняемый компонент
`readProject` сам имеет свой пакет Component; предмет его работы не определяет
класс реализации читателя. Аналогично устроены читатели Repo и Domain.

## Поэтапная миграция

Assessment возвращает свидетельства и не меняет файлы пакета или режим сборки.
Переходный пакет получает предупреждения о несоответствии стандарту.
Полностью подтверждённая и успешно применённая ревизия автоматически закрепляет
strict; последующая регрессия не возвращает transition. Код ошибок исполнения
сценария не подменяется предупреждением о структуре.

Подробная политика принадлежит [сборке](../../../build/notes/compilation.md),
сохранение и применение — [сессии пакета](../../../sessions/notes/revisions.md).
Строгость родителя не распространяется автоматически на дочерние пакеты.
Проверка одного уровня не подтверждает миграцию всего поддерева.

## Границы подтверждения

Структурные проверки не являются универсальной автоматической оценкой смысла.
Незавершённая применимость трёх обязательных TODO Component описана
[у Component](../../component/notes/verification.md). В руководстве сценариев
также остаются [неавтоматизированные правила](../../specs/scenarios/notes/authoring-history.md).
Наличие этих текстов нельзя считать подтверждением поведения.
