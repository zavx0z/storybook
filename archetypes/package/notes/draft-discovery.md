# Как находить пакеты и изолировать их ошибки

Storybook читает выбранные физические корни, `package.json` и workspaces.
Обнаружение не исполняет код пакета и не читает проектные декларации Storybook.
Порядок шаблонов workspaces и сортировка совпадений по пути задают порядок
пакетов; повторные совпадения сводятся к одному владельцу.

```mermaid
flowchart LR
  roots["Выбранные корни"] --> find["package.json и workspaces"]
  find --> good["Проверенный пакет"]
  find --> bad["Локальная ошибка"]
  good --> revision["Своя ревизия"]
  bad --> keep["Последний рабочий снимок"]
```

Каждый найденный пакет виден по своему точному `package.json#name`.
`label` читается при наличии. Реальные публичные директории,
модульный TSDoc, contract и spec добавляют собственные представления;
отсутствие этих файлов не скрывает пакет. Нормы размещения принадлежат
[структуре Archetypes](../../notes/draft-structure.md).

Общий watcher следит за составом workspaces, `package.json`, директориями и
документами. При обновлении ошибка одного пакета сохраняет его последний
проверенный состав и рабочую ревизию; исправные соседи продолжают работу.
Первое подключение проверяется строго. Дублирующаяся identity, выход за корень
и symlink traversal отклоняются. UI и MCP получают одну диагностику своего
пакета. Изменение общего исходника затрагивает только его действительных
потребителей. Второй граф, Workbench или MCP registry не создаётся.
