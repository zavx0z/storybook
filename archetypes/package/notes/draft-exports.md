# Публичные пути и владелец реализации

Component публикует собственный основной `index.ts` или `index.tsx` и основные
контрактные типы. Частные помощники остаются в `src`; ресурсные экспорты сохраняют
назначение своих ресурсов.

Domain может предоставлять понятный подпуть к публичному входу физически вложенного
пакета. Например, `@webxr/ui/button` разрешается через `exports` UI прямо в
`./button/index.tsx`. У button остаются собственные `package.json`, зависимости,
контракты, сценарии и идентичность. Промежуточный файл-реэкспорт не нужен.

[Читатель входов](../index/index.ts) различает `owned` — собственный файл и
`forwarded` — точный публичный вход вложенного владельца. Во втором случае
результат сохраняет владельца реализации и его экспортный путь. Контракты читаются
у реализации; типы и документация домена их не подменяют. Вложенный владелец обязан
входить в обнаруженный состав корневых workspaces Repo; это проверяет общий сценарий Package.

Частный файл дочернего пакета, не объявленный его exports, не становится публичным
через родителя. Выход за корень, символические ссылки и отсутствующие файлы
сохраняют отрицательные результаты проверки. Повторные пути одной реализации
в карте одного владельца запрещены; условные ветви одного пути не являются дублями.

Штатный exports не перенаправляет на имя соседнего пакета и не допускает `../`.
Реэкспортные фасады и aliases ради короткого пути не добавляются. При публикации
прямые файловые цели должны присутствовать в установленном дереве родительского
пакета; workspaces сам по себе не гарантирует их включение в артефакт.

Исходник основного контракта остаётся в contract/input.ts или contract/output.ts.
Index публикует основные контрактные типы через export type вместе с реализацией.
Вспомогательные типы не получают дополнительных кодовых входов автоматически.
Отсутствующий по смыслу вход или выход не требует фиктивного файла.
