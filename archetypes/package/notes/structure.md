# Общая структура Package

Package — единая структурная форма Repo, Domain и Component. Он владеет
идентичностью, публичными входами, зависимостями, документацией и собственными
проверками. Наличие вложенных пакетов не создаёт отдельный класс Container.

[readPackage](../index.ts) читает манифест, модульный TSDoc, публичные входы и
состав workspace Repo, Git-границу, происхождение экспортов и ссылки контрактов без исполнения
потребительского кода. Вложенные владельцы
сохраняют собственные identity. Читатель возвращает структурные факты
и при отсутствии exports.

Согласованная норма допускает Repo без собственного публичного API и exports.
Текущий общий сценарий Package пока требует объект exports у каждого пакета,
до условных разделов Repo, Domain и Component. Применимость этой проверки
ещё предстоит привести к согласованной норме; текст не означает, что такой Repo
уже проходит действующий сценарий.

[Сценарий Package](../spec/scenario.spec.ts) проверяет identity, документацию,
принадлежность публичных файлов и отсутствие дублирующих кодовых путей.
Условные разделы Repo, Domain и Component раскрывают специализированные правила.
Применимость и примеры выражены в коде этого сценария; результат относится
к конкретному запуску. Интерфейс и сборщик используют его полный отчёт
без собственного реестра классов или выбора по названию отдельного теста.
Текущий [вход MCP](../../../mcp/rest/README.md) раскрывает исходник сценария,
но не отчёт выполненных проверок.
[Правило экспортов](draft-exports.md) различает собственную реализацию и публичный
путь домена к вложенному компоненту. Неизвестные формы exports сохраняются
непроверенными, а не объявляются соответствующими стандарту.

Применимые требования к контрактам и исполнению принадлежат специализации.
Незавершённые проверки API, состояния и обогащения данных описаны
[у Component](../../../component/notes/verification.md). Файловая полнота Package
не подтверждает эти свойства.
