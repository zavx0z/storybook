# Как оформить спецификацию владельца

Если у владельца есть собственный `spec`, он располагается непосредственно
в его пакете. Собственный spec не обязателен для Domain. Сценарий
пишется по [примеру Archetypes](../spec/scenario.spec.ts), а правила зависимостей и
контрактов имеют свои заметки-владельцы.

Проверки внутренних механизмов, включая интеграционные тесты, размещаются
отдельно в `test` пакета. Разделение определено в
[правилах структуры](../../notes/development.md#спецификации-и-тесты-реализации).

[readSpecGuide](../index.ts) принимает путь к владельцу. Поиск `spec`, выполнение
Bun Test и полный отчёт принадлежат [читателю App](../../../app/spec-reader/README.md).
Archetypes собирает из этого отчёта описание существующих файлов, кодовые примеры
и состояние правил написания. При отсутствии сценария возвращается `null`.

Необязательные сценарии Domain могут проверять особые правила области и не иметь
собственного preview. Общие проверки структуры принадлежат Archetypes и не
требуют повторяющего их spec в каждом домене.
Сценарии Component выполняют его публичное поведение. Repo сохраняет свой стандарт
организации пакетов; Project проверяется как набор независимых Repo.
