# Сценарии

## Чтение через отладчик

`readScenario({path})` вызывает `src/inspect.ts`, который запускает настоящий `bun test` с отдельным Inspector WebSocket,
без подмены `bun:test`. Штатный `TestReporter` возвращает группы, тесты,
родительские связи и результаты запуска. В заданных точках остановки сборщик
читает доступные неглобальные области видимости через `Runtime.getProperties`.

На сценарии package.json получены `props`, `runtime`, `result`, `fields` и
`extraFields`, а также успешные результаты всех пяти тестов. Getters не вызываются;
объекты раскрываются до пяти уровней с явной отметкой ограничения.
Можно передать `lines` со строками остановок; по умолчанию запрос отправляется
для каждой строки выбранного файла. Инспектор разрешает доступные позиции.
Автоматическое сопоставление исходного TypeScript через sourcemap пока не реализовано.
Проверки запуска, событий и чтения локальных значений находятся в
`test/inspector-execution.test.ts`, проверка окружения отладчика — в
`test/inspector-environment.test.ts`. Их вспомогательные файлы находятся в
`test/fixture`. В `spec/scenario.spec.ts` остаётся каркас проверок данных результата.

## Подготовка данных и тело теста

Общие неизменяемые данные, не зависящие от варианта или отдельного запуска теста,
определяются на уровне модуля. Например, путь к общей директории фикстур
вычисляется один раз вне тела теста.

Данные вариантов задаются параметризацией групп и тестов. Тело теста вызывает
проверяемую функцию с данными сценария и проверяет полученный результат.
Ресурсы, требующие отдельного создания и очистки для каждого теста, сохраняют
свой жизненный цикл и не становятся общим изменяемым состоянием модуля.

## Предстоящая проверка

Каждый пропуск теста или группы сопровождается TSDoc с `@remarks`
непосредственно перед объявлением. Заметка объясняет условие пропуска
и причину, по которой проверка не выполняется в этом случае.
Это относится и к условным пропускам, и к постоянно отключённым тестам.
Наличие непустого `@remarks` проверяется в [спецификации пропусков](../spec/skip.spec.ts).
Смысл пояснения пока оценивается при чтении: тест проверяет наличие заметки.

В спецификации сценариев нужно проверять структуру самого теста:
общая подготовка неизменяемых данных не должна повторяться внутри его тела.
Эта проверка пока не реализована.
