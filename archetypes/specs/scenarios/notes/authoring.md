# Где вызвать функцию и как проверить результат

```mermaid
flowchart TD
  props["Данные варианта"] --> call["Вызов функции в describe"]
  call --> result["Общий result этого варианта"]
  result --> first["Тест одного свойства"]
  result --> second["Тест другого свойства"]
  result --> full["Полный результат"]
```

Сценарий импортирует проверяемую функцию и напрямую вызывает её внутри
callback `describe.each`, до регистрации тестов. Асинхронный вызов ожидается
в `async` callback группы. Полученный `result` используется всеми тестами
этого варианта; каждый тест проверяет результат своего варианта.

Декларация `runtime` и обёртка `test.each([{runtime: ...}])` для запуска
функции не используются. Сборщик `readScenario` наблюдает прямые вызовы,
их аргументы и результаты автоматически; ручные mock и spyOn не требуются.
`test.each` применяется только к действительно параметризованным проверкам данных.

```ts
describe.each([
  {name: "Пакет", props: {path: resolvePath("fixture/repository/package")}},
])("$name", async ({name, props}) => {
  const result = await readSpec(props)

  test("Возвращает данные сценария", () => {
    expect(
      result?.scenario,
      `Спецификация, которой владеет ${name.toLowerCase()}, должна возвращать данные сценария`,
    ).toBeDefined()
  })
})
```

Общие неизменяемые данные, не зависящие от варианта или отдельного запуска теста,
определяются на уровне модуля. Например, путь к общей директории фикстур
вычисляется один раз вне тела теста.

Данные вариантов задаются параметризацией групп. Тело теста проверяет результат,
уже полученный прямым вызовом функции в группе.
Ресурсы, требующие отдельного создания и очистки для каждого теста, сохраняют
свой жизненный цикл и не становятся общим изменяемым состоянием модуля.

Прямой вызов перед тестами можно увидеть в [сценарии Specs](../../spec/scenario.spec.tsx)
и [сценарии трассировки](../spec/scenario.spec.ts).
