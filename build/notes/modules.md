# Единая идентичность модулей

[Shared identity](../shared-module-identity.ts) связывает публичные входы платформы с общими модулями; [проверки](../shared-module-identity.test.ts) фиксируют её границы.

Сборка фиксирует канонические физические пути зависимостей через
[канонизацию исходников](../package-build.ts). Единое разрешение исходников
и общая runtime identity — разные свойства.

[Граф владельцев компилятора](../compiler.ts) читает объявленные зависимости
и фактические установки. Обычный диапазон версий сохраняет локального владельца,
если Bun установил ссылку на его исходники вне `node_modules`; имя и версия
проверяются по манифесту цели. Ссылки в npm store не расширяют граф исходников.
Проверки [компилятора](../compiler.test.ts) раскрывают JSX adapter, транзитивные
ссылки, npm store и отказ при несовместимой версии. Наличие пакета в окружении
без объявления зависимости не даёт права использовать его как владельца.

Оболочка, пакет и сгенерированный JSX используют общие immutable browser-модули
владельцев из `STORYBOOK_SHARED_BROWSER_OWNER_PACKAGES` в
[исполняемом составе kernel](../shared-module-identity.ts). Владельцы вне этого
состава собираются как зависимости оболочки или потребителя; в частности, UI
не входит в общий kernel. Канонический путь такого исходника не означает,
что оболочка и потребитель загрузили один runtime-модуль.

Повторное включение runtime создаёт отдельные внутренние метки и объекты,
даже если исходный файл один. Поэтому значения, созданные для общего runtime,
должны использовать его же публичный вход.

Две идентичности одного владельца, неоднозначное разрешение зависимости,
узел с чужой внутренней меткой и несовместимый протокол отклоняются.
Псевдонимы совместимости не добавляются.

Обязательные `@zavx0z/jsx/jsx-runtime` и `jsx-dev-runtime` принадлежат домену
JSX: они открывают index.ts доменов runtime и development, которые назначают
protocol-имена default-реализациям внутренних компонентов.
Идентичность самих компонентов сохраняется через их публичные входы;
произвольные exports во вложенные чужие пакеты не получают разрешения автоматически.
Compiler и Bun adapter остаются серверными владельцами и в browser kernel не входят.
Условные входы для browser выбираются в порядке exports по browser/import/default;
Bun-ветка не подставляется в браузерную сборку. Fragment и таблица событий
участвуют в той же общей identity, что и runtime.
Сборка получает factory из default-экспорта точного пакета `@jsx-compiler/bun`;
его входные и выходные типы остаются именованными контрактами владельца.

## Обновление общей оболочки

Ревизия потребителя сохраняет точную платформу (`sharedModuleEpoch`). Общая
оболочка получает собственную идентичность исходников, компилятора и темы
(`hostModuleEpoch`). Её обновление через `storybook:shared` собирает текущий
код оболочки для сохранённых платформ, используя проверенные immutable модули.
Сборки потребителей для этого не запускаются.

`check(live:false)` подготавливает набор. `check(live:true)` публикует единый
указатель на него и отправляет событие страницам. Подготовка и ошибка записи
сохраняют опубликованный набор. Запуск сервера читает опубликованный receipt;
кандидат доступен только просмотру кандидата. Сам факт публикации ещё не
подтверждает применение в браузере.

[Архив receipts](../shared-browser-receipt.ts) сохраняет точные пары платформы
и оболочки вместе с digest файлов. Отсутствующие сведения старой ревизии
не восстанавливаются догадками по bundle: такой странице требуется миграция.

Архивная платформа проверяется по собственному сохранённому составу модулей,
epoch и хешам immutable файлов. Переименование пакета или удаление исходника
не отменяет уже собранную платформу. Текущий список владельцев проверяет новые
сборки и не используется для переопределения состава архива. Resolver сохранённой
платформы направляет её specifier прямо в сохранённый URL; подстановка новой
реализации при отсутствии требуемого общего модуля запрещена.

Имена файлов Bun не считаются доказательством неизменности байтов. Перед публикацией
проверяется SHA-256; существующий файл никогда не перезаписывается. Каждый граф Bun
повторно формируется в пространстве имён, определённом результатом сборки.
Это также исключает повторное использование старого адреса из browser cache. Импорты и source maps остаются результатом штатного bundler.

Оболочка обновляется для живых browser leases и явно запрошенных платформ.
Неиспользуемая история не участвует в этой проверке. Повреждение старой платформы
остаётся диагностикой и требует применения новой ревизии её пакета; её открытая
страница не получает команду загрузить неподтверждённую оболочку. Независимый
пакет может применить исправную платформу. Общий shared check не заявляет полного
успеха, пока нужные живым страницам платформы не подтверждены.
