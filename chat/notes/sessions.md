# Адресные беседы

Чат принадлежит каноническому адресу предмета внутри одного Project. Корень `/`
обозначает Project, остальные адреса разрешаются по действующему каталогу.
Выбор представления, секции Inspector, варианта сценария и ревизии не создаёт
новую беседу. Чат расположен первой секцией Inspector и доступен также на
страницах Repo и директорий.

История хранится в `chats` внутри материального Project, независимо от cache
Storybook и сборочных артефактов. Каждый адрес имеет собственный JSON-файл;
он появляется после первого сообщения. История содержит сообщения и сведения,
необходимые для восстановления ACP-сессии. Секрет MCP-подключения хранится
только в памяти сервера и окружении соответствующего процесса.
Черновик хранится отдельно по identity беседы в локальном состоянии браузера.

При физическом переносе владельца новый адрес сам по себе не открывает файл
прежнего адреса. Владелец приложения передаёт [ChatSession](../session/index.ts)
точное соответствие прежних и текущих адреса и cwd; текущий адрес проверяется
каталогом. Перенос касается только этой беседы, создаёт новый файл атомарно без
перезаписи другой истории и сохраняет прежний файл для восстановления. Id,
сообщения и ACP sessionId сохраняются, поэтому браузерный ключ черновика
остаётся прежним. Повтор операции не стирает новые сообщения. Активный turn
нужно завершить до переноса; пустое чтение не создаёт файл и не запускает агента.
Следующее сообщение пробует штатное восстановление ACP в новом cwd. Ошибка
восстановления остаётся видимой ошибкой беседы и не начинает новый разговор.

Настройки модели и уровня мышления загружаются при явном открытии выбора через
ACP `configOptions`. Подготовка создаёт или восстанавливает сессию, но не вызывает
`session/prompt`. Выбор применяется через `session/set_config_option`; список
допустимых уровней после смены модели возвращает агент. Во время ответа настройки
не меняются. Начальные значения определяет адаптер, а выбранные — его сессия;
глобальный конфиг Codex не переписывается.

Контекст показывается по `usage_update.used` и `usage_update.size`, включая
подтверждённые данные восстановления. Последние значения сохраняются с беседой.
До получения данных индикатор показывает их отсутствие, а не выдуманный ноль.
При смене модели старый лимит не выдаётся за лимит новой модели.

Composer использует многострочный textarea: Enter отправляет сообщение,
Shift+Enter оставляет новую строку, подтверждение IME не отправляет текст.
Одна круглая кнопка переключается между отправкой и остановкой. Сообщения
пользователя имеют отдельный фон; Markdown и код используют существующий
компонент отображения с подсветкой.

Создание представления не запускает модель. Первое сообщение открывает
подключение к Codex через готовый ACP-адаптер. Следующие сообщения используют
ту же сессию. Восстановление сохранённой сессии не подменяется новым разговором;
ошибка восстановления показывается пользователю. Повтор HTTP-отправки с тем же
идентификатором не создаёт второе исполнение сообщения.

Одновременно в беседе выполняется один ответ. Разные адреса независимы.
Переход страницы и отключение потока состояния снимают подписку, сохраняя работу.
Остановка относится к выбранной беседе; запросы разрешений отображаются
в её Inspector и получают только явно выбранный пользователем ответ.
После прерывания процесса незавершённое сообщение автоматически не повторяется.

Приложение создаёт для ACP-сессии отдельное MCP-подключение. Ключ этого подключения
связывает обращения с назначенным предметом. Пустой вызов `storybook({})`
открывает его корень; сервер проверяет каждый выбранный адрес по каталогу.
Общие правила пакетов и контрактов доступны отдельными разрешёнными ссылками.
Этот MCP-вход предоставляет предметное чтение; глобальные управляющие инструменты
Storybook в него не регистрируются.

MCP-доступ и собственные средства Codex имеют разные границы. Режим исполнения
и подтверждения операций задаются через штатную конфигурацию адаптера и Codex.
Передача `cwd` сама по себе не устанавливает файловую изоляцию. Отдельного
репозитория ACP и собственной реализации протокола здесь нет.
