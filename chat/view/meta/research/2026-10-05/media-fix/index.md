# Файловый drop, понятные ошибки и восстановление медиа

После предыдущей публикации Владимир проверил настоящее использование:
кнопка вложения выглядела белым квадратом, файловый drop отсутствовал,
а отправленное изображение осталось с `Internal error`. Предыдущие проверки
истории и previews не покрывали эту полную цепочку.

## Исправления у владельцев

- Chat использует IconButton вместо неоформленного native button. Стандартные
  drag events передают `onFiles` снимок FileList; подготовка использует тот же
  bounded `filesToMedia`, что системный picker, без автоматической отправки.
- С прямого разрешения Владимира DOM/Browser/HTML Renderer получили общий
  incoming file drag-and-drop через существующий projection hit-testing и тот
  же Document. Поведение и границы описаны в
  [контракте Browser](../../../../../../../immersive/browser/drag-and-drop.md).
- Ошибка PNG оказалась отказом `session/load`: точная native-сессия Codex была
  архивирована. Её принадлежность подтверждена cwd, executor и исходным вопросом.
  Сессия восстановлена штатным Codex API, контекст не заменялся новым.
  Уже принятая очередь выполнилась; сохранён ответ по изображению, pending пуст.
- ACP раскрывает понятную причину: «Сессия Codex архивирована. Восстановите её
  из архива, чтобы продолжить беседу». `code`, `data`, `cause` сохраняются;
  сообщение ограничено 2048 символами. Frontend не прячет причину за HTTP-префиксом.
  Старый `Internal error` отображается общим русским объяснением; исходные события
  не переписываются и им не приписывается отсутствующая в журнале причина.

## Два дефекта повторной загрузки истории

Восстановление выявило два формата native replay. Bootstrap и вопрос склеивались
в одну строку на 39517 символов. Кроме того, установленный Codex ACP возвращает
изображение как текст `[@image](data:...;base64,...)`: реальная строка имела
968507 символов. Это был уже другой этап, после успешной отправки PNG.
Большие служебные/кодированные строки попадали в обычное представление текста;
страница теряла отзывчивость, её пришлось переоткрывать.

Session теперь сопоставляет собственный реально начатый input по полной
точной форме, включая байты изображения. Подтверждённый replay раскрывается
как context с исходными типизированными блоками. Пользовательский вопрос и
изображение остаются в исходном canonical сообщении. Произвольные Markdown
ссылки не декодируются. Также покрыто первое сообщение с bootstrap и изображением.

Соответствия вычисляются при записи/rebuild и сохраняются в disposable SQLite
индексах. Header-страницы не читают payload; lookup и очистка используют индексы.
Исходный журнал, raw evidence, identity и содержимое пользовательских записей
сохраняются. На реальных копиях проверены оба дефекта, порядок context/user,
позднее доказательство, неоднозначность, несовпадающие и ещё не начатые inputs.

## Живая проверка

[CDP file drop](file-drop.json) использовал настоящее `Input.dispatchDragEvent`
с контролируемым PNG. В dragover файлы защищены (`files=0`, marker `Files`),
в drop доступен один File. Native default отменён, effect `copy`, область
подсвечена, появился один [preview](composer.png). Draft не изменился;
запросов prompt — **0**. Preview открывался на область чата, закрывался,
тестовое вложение удалено.

После повторного native load проверены настройки модели: два settings,
без ошибки и pending. Модель/уровень не менялись: `gpt-6-astra` / `medium`
совпали до и после проверки. Панель закрыта, draft пуст, вложений и overlays нет.
На странице осталось 31 history header, один видимый body, 695 текстовых символов.
Сессия idle, error null; Runtime observer ошибок не получил.

Последний [process snapshot](../process-memory-media-final-healthy.json):
95,39 MiB private footprint. [JS snapshot](../media-final-healthy.json):
26,92 MiB used heap, 1,497 ms task duration за пять секунд. Это **новый процесс
и timeOrigin после восстановления вкладки**, а не сравнение в том же процессе
с прежним замером. Принудительная GC не вызывалась.

Основная сборка и применение завершены; рабочая revision
`43f8e4719d9276e93b6ad054`. До исправления replay применение/чтение в старой вкладке
завершалось timeout; после восстановления и исправлений полный путь прошёл.
Сохраняется прежнее transition-warning корневого Immersive об основном API-входе
(оно присутствует в `tmp/history-prepublish-status.json` до этого среза).

## Проверки и пределы

Независимые прогоны: DOM/Browser/HTML — 478 pass; ACP — 36 pass и один условный
skip; browser client — 20 pass; composer/media — 11 pass; replay — 23 pass
и условные сценарии. Дополнительный прогон archive/replay и query-plan очистки:
17 pass. Typecheck затронутых владельцев и diff-check прошли. Количества разных
прогонов не суммируются: часть сценариев пересекается.

Native file clipboard, исходящий drag, `DataTransfer.items`/`setDragImage`
не добавлялись. Произвольные мегабайтные однострочные документы требуют своей
проверки source viewer; этот срез устраняет ошибочное автоматическое отображение
изображений и служебного replay как такого текста.
