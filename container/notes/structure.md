# Композиция компонентов

Container реализует одно целое через композицию компонентов и вложенных
контейнеров с компонентами. Наружу он предоставляет собственную реализацию
через default и именованные типы своего контракта.

Domain раскрывает именованный API предметной области. Container использует
части для собственного поведения; их реализация и контракты сохраняют владельцев.
Дочерние компоненты не получают дополнительные публичные адреса через контейнер.

Принадлежность частей выражена физической вложенностью пакетов и составом
корневого workspace Repo. Использование внешней зависимости не делает её
внутренней частью контейнера. Частные helpers в src не являются самостоятельными
частями и сами по себе не превращают Component в Container.

Пример устройства:

```text
container/
├── index.ts              собственная реализация целого
├── contract/             её вход и выход
├── spec/                 применение и поведение целого
├── component/
└── nested-container/
    └── component/
```

## Чтение и проверка

[readContainer](../index.ts) использует факты публичного читателя Component.
Он возвращает собственный вход, контракты, сценарии и непосредственные части
с runtime-импортами из реализации целого. Читатель не исполняет исследуемый код
и не записывает класс в данные пакета.

[Сценарий Package](../../package/reader/spec/scenario.spec.ts) различает
Component без самостоятельного вложенного состава и Container с собственной
реализацией и принадлежащими частями. Раздел Container проверяет участие этих
частей и ту же внешнюю границу default плюс типы. Собственный сценарий
показывает результат композиции, включая использование вложенного контейнера.

Файловая вложенность и импорт не доказывают фактический вызов или полноту
поведения. Каждая вложенная часть сохраняет собственный контракт и проверки;
проверка родителя не заменяет проверку всего поддерева.
Читатель Container сам является Component, который исследует контейнеры.
