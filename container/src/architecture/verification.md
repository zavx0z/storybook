# Композиция компонентов — Чтение и проверка

readContainer использует факты публичного читателя Component.
Он возвращает собственный вход, контракты, сценарии и непосредственные части
с прямыми runtime-импортами из собственных исходников целого. Пустой список
прямых импортов у части не означает, что она не участвует через другую часть.
Читатель не исполняет исследуемый код и не записывает класс в данные пакета.

Сценарий Package различает
Component без самостоятельного вложенного состава и Container с собственной
реализацией и принадлежащими частями. Раздел Container требует для каждой
непосредственной части runtime-связь от собственных исходников целого: прямую
либо проходящую через другие достигнутые принадлежащие пакеты. Проверка
повторяется у каждого вложенного Container; отсоединённый цикл частей,
type-only связь, реэкспорт API и импорт внешнего пакета не заменяют участия.
Внутренние browser и worker исходники тоже могут принадлежать целому
и не обязаны импортироваться его default-входом. Их участие в исполнении
не разрешает дополнительные публичные входы контейнера. Сценарий сохраняет внешнюю границу default
плюс типы и показывает результат композиции, включая вложенный контейнер.

Private src-вход с единственным runtime default может передавать реализацию
части в другое место исполнения, как browser entry, загружаемый после сборки.
Это структурная связь с принадлежащей частью; публичный фасад, named-каталог
и type-only реэкспорт таким свидетельством не являются. Само наличие private
входа не подтверждает его загрузку: она проверяется сценарием владельца.

Это необходимое структурное свидетельство, а не доказательство фактического
вызова: Reader не знает, какой из отдельных исполняемых входов активируется
в конкретной среде. Собственный поведенческий сценарий подтверждает результат.
Каждая вложенная часть сохраняет свой контракт и проверки; проверка родителя
не заменяет проверку всего поддерева.
Читатель Container сам является Component, который исследует контейнеры.
