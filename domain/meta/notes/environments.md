# Входы сред одной сущности

Каждая поддерживаемая среда Domain имеет собственный публичный вход:
одну основную реализацию и соответствующий ей протокол.
Условия `package.json#exports` выбирают вход, а не объединяют экспорты файлов.
Средовые реализации сохраняют общий предмет и могут предоставлять разные
возможности в соответствии с обязанностями среды.

Для обсуждаемого Chat выбраны `web.ts` и `server.ts`, без обязательного
общего `index.ts`. Эти имена не вводятся как универсальный перечень сред.
Имя исходного файла и условие exports — разные понятия:
условия выбираются по фактически поддерживаемым окружениям и инструментам.

Для единственного общего входа достаточно `index.ts`; его наличие не доказывает
Domain. Переносимый Container с одной реализацией сохраняет единственный
индексный вход. Группировка функций и режимы development/production не создают
новую среду; частный файл в src не становится публичным входом из-за своего имени.

## Выбор и проверка

Используются штатные условия поддерживаемых инструментов с сохранением порядка
их объявления. Повтор одного файла в нескольких ветвях требует смысла:
выбора API либо ограничения доступности. Универсальному входу достаточно
`".": "./index.ts"`. Условие node может ограничивать общий серверный вход;
Bun также распознаёт node. Отдельная ветвь bun нужна для специфичной реализации
или Bun-only API. Совпадение условия не доказывает работоспособность пакета.

Каждый вход проверяется по собственному разрешённому графу:
браузерная реализация не получает серверные зависимости, серверная — случайные
требования браузерного окружения. Общие переносимые зависимости сохраняются.
Типовое разрешение, подготовка к исполнению и фактическое использование
дают разные свидетельства.

Документация и протокол относятся к выбранному входу. Отсутствие общего индекса
не является отсутствием документации, если реальные входы документированы.
Читатели сохраняют документы и протоколы каждого входа; интеграция с
представлениями отслеживается [у Package](../../../package/meta/notes/archetype-transition.md).

Не создаются файлы для воображаемых сред. Domain с одной реализованной средой сохраняет явный средовой вход, протокол
и предметные свидетельства; фиктивная вторая реализация не используется
ради классификации. Число сред само по себе не подтверждает общий предмет.

## Внешние протоколы и примеры

Фиксированные подпути JSX выражают требования транслятора,
а не самостоятельные среды Domain. Их сохранение и проверка описаны
[у Package](../../../package/meta/notes/draft-exports.md#внешние-протоколы).

JSX служит примером применения требований, но его имена не встраиваются
в классификатор. Cosmos подтверждает возможность средовых реализаций одного
пакета; его структура, незавершённые части и условия cosmos:* не становятся
универсальным шаблоном. Миграция Cosmos планируется отдельно.
