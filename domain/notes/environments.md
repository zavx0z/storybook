# Среды выполнения и внешние протоколы

Одна предметная область может предоставлять разный API для разных сред.
Файл входа собирает реализации и соответствующие типы этой среды. Условия
package.json#exports выбирают один вход, а не складывают несколько файлов.
Реализации и набор экспортов разных сред не обязаны быть одинаковыми.

Для единственного входа достаточно index.ts. Дополнительные корневые файлы
нужны действительным различиям сред, например browser.ts и server.ts;
группировка функций и режимы development/production не являются новой средой. Приватный src не становится
публичным входом среды только из-за имени файла.

Используются штатные условия поддерживаемых инструментов. Повтор одного файла
в нескольких ветвях требует смысла: выбора другого API либо ограничения
доступности. Универсальному входу достаточно ".": "./index.ts". Условие node
может ограничивать общий серверный вход; Bun также распознаёт node. Отдельная
ветвь bun нужна для специфичной реализации или Bun-only API. Совпадение условия
не доказывает работоспособность пакета в данной среде — нужна её проверка.
Не требуется создавать файлы для воображаемых сред.

## Протокольные подпути

Обязательное имя внешнего протокола не является произвольным alias. При native
automatic JSX TypeScript/Bun требуют именно ./jsx-runtime и ./jsx-dev-runtime;
путь ./dev их не заменяет. Эти подпути направляются на index внутренних доменов.
Корневые runtime.ts/development.ts ради перенаправления не создаются.
Имена jsx/jsxs/jsxDEV/Fragment собираются доменами из default-компонентов.

Физическое размещение реализации выбирает владелец. Собственный компилятор
может выдавать прямые импорты, но это не отменяет оставшихся потребителей
стандартного протокола: проверки типов и JSX в сценариях. Перед удалением входа
необходимо проверить все эти роли. Ручной Runtime import во всех TSX не является
принятым требованием и не вводится ради косметического сокращения exports.
Отладочный вход сам по себе не доказывает наличие отдельной диагностики:
его фактическая обработка metadata должна быть видна в реализации.

## Граница обобщения

JSX служит исполняемым примером правила, но его имена не встраиваются в
классификатор Archetypes. Cosmos показывал возможность средовых входов;
его незавершённое устройство и условия cosmos:* не являются универсальным шаблоном.
Будущая миграция Cosmos выполняется отдельно по общей модели.
