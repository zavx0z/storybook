# Предметная область и публичный API

Domain выражает одну область с общими понятиями, правилами и отношениями.
Поддомен остаётся Domain. Родственные возможности образуют область: например,
планирование, позиции и проверка контрактов слотов относятся к Slot, а не к
несвязанным верхнеуровневым пакетам. Тематическое сходство имён само по себе
не доказывает принадлежность.

## Сборка API

Домен владеет публичным составом области. Его index собирает реализации и типы
через публичные входы владельцев, назначая реализации понятное имя:

```ts
export {default as Button} from "@ui/button"
export type {ButtonProps} from "@ui/button"
```

Наличие runtime-реэкспортов в этом файле не превращает Domain в Component или
Container. Реэкспорт не переносит реализацию и не создаёт её копию. Имя функции в исходнике
компонента и имя в API области имеют разные назначения. Типы также остаются
у своих владельцев, хотя доступны потребителю через домен.

Доменный вход не реализует собственную бизнес-логику и не запускает lifecycle.
Если нужно соединять экземпляры, подписки или состояние, эта исполняемая
композиция получает собственного владельца: Component без принадлежащих
вложенных частей либо [Container](../../container/notes/structure.md), который
композирует принадлежащие компоненты и вложенные контейнеры с компонентами в одно
целое. Частный модуль с эффектом не позволяет
скрыть такое поведение за внешне декларативным index.

Внутренние пакеты импортируют реализации и контракты непосредственно у владельцев.
Обратный импорт из публичного фасада родителя для этого не нужен. Общий Fragment
или другая зависимость может участвовать в API нескольких областей, сохраняя
одного владельца и одну identity; зависимость не становится собственностью
потребителя. Приватные исходники чужих пакетов не раскрываются.

## Проверка области

[Читатель](../index.ts) показывает локальное поведение и происхождение API.
[Сценарий Package](../../archetypes/package/spec/scenario.spec.ts) проверяет общие сведения,
разрешение символов и публичные границы. Класс не записывается в манифесте.
Собственный spec Domain не обязателен: общие структурные проверки не копируются
в каждую область. Существующие предметные сценарии выполняются обычным исполнителем;
их ошибки не скрываются и наличие не подменяется успехом.

Состав выводится из [workspace Repo](../../archetypes/repo/notes/structure.md), а не из
workspaces домена. Различия сред описаны [отдельно](environments.md), механика
публичных входов — [у Package](../../archetypes/package/notes/draft-exports.md).
Файловая проверка не доказывает полноту смысла всех предметных правил.
