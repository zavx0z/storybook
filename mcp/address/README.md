# Адресация MCP

MCP адресует зарегистрированный пакет целиком. Его адрес берётся из общего
каталога Storybook и заканчивается на границе пакета. Наличие директории внутри
пакета не делает её доступной по MCP. Раскрытие внутренней структуры — следующий
этап, который этот контракт не реализует.

Уровни адреса разделяются `/`, например `storybook/archetypes/package`.
Точка остаётся частью имени: `library.v2` не означает два уровня.
Параллельная запись тех же адресов через точки не поддерживается.
Это сохраняет связь с публичными путями Storybook и не требует от агента
переводить адрес из одного соглашения в другое.

В MCP-адресе нет query-параметров, fragment, начального и конечного слеша.
Имена сценариев, вариантов, инспекторов и внутренних директорий в него
не добавляются. Пустой вызов инструмента открывает независимый [Root](../root/README.md);
чтение адреса использует общий [Children](../children/README.md) и может
перечислить только вложенные самостоятельные пакеты. Адрес передаётся полем path,
совпадающим с полем path выбранного направления в ответе.

Окно MCP определяет пакет-владелец открытой страницы по тому же каталогу.
Параметры страницы управляют интерфейсом, но не входят в показанный запрос MCP.
Прямой MCP-вызов с параметрами или внутренним путём отклоняется явно.

[Исполняемый контракт](spec/scenario.spec.ts) проверяет границу пакета,
разделитель и отклонение лишних частей адреса.
