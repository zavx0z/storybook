# Пакетный HTTP-вход MCP

Этот этап раскрывает только зарегистрированные пакеты. Правило адресации
принадлежит [Address](../address/README.md). Подключающий сервер передаёт
пакетные узлы общего каталога; отдельного реестра и обхода директорий здесь нет.

Пустой запрос возвращает корневые пакеты. Запрос с node выбирает точный пакет
и перечисляет только непосредственно вложенные пакеты. Каждая запись содержит
адрес node и название title. Внутренние директории, вкладки, сценарии и темы
пока не раскрываются. Query, fragment, action и input отклоняются.

MCP-прокси передаёт этот JSON без предметных преобразований. Чтение адреса
не исполняет сценарии и не запускает сборку. Существующие читатели
[сценариев](scenarios/README.md) и [спецификаций пакета](package/index.ts)
сохраняют собственные контракты, но не доступны через адреса этого этапа.

## Журнал

Журнал MCP хранит последние 20 запросов: имя инструмента, параметры, время,
статус и полный публичный ответ без обрезки по длине. Окно журнала показывает
одну выбранную команду. Ответ целиком отображается в CodeEditor с подсветкой JSON;
окно не формирует представление для приложения. Кнопки переключают команды,
а не страницы ответа; все 20
записей остаются в истории. По умолчанию показывается последняя команда,
выбор более старой сохраняется при новых обращениях. Служебные
секреты и внутренние адреса проходят обычную очистку публичной границы MCP.
Для `storybook_capture` журнал сохраняет метаданные и `captureId` без base64,
отдельно загружает PNG через авторизованную browser-сессию и показывает превью.

Второй режим [окна MCP](../../workbench/mcp-window/README.md) определяет пакет
открытой страницы по canonical graph. В показанный запрос входит только
пакетный адрес; внутренние директории и параметры интерфейса туда не попадают.
Корневая страница соответствует пустому запросу. Browser-сессия обращается
к тому же REST-обработчику и не добавляет запись в журнал вызовов агента.

HTTP-приём записи журнала допускает до 8 МиБ в UTF-8 на запись, отдельно от
лимита 64 КиБ обычных управляющих команд. Размер проверяется и по заголовку,
и при чтении потока; превышение отклоняется целиком, без усечения ответа.

Статус сервера содержит requestJournal: состояния последних записей, размеры
входов и ответов в UTF-8 и последнюю ошибку приёма записи. Сводка не включает
содержимое ответов и доступна независимо от работоспособности окна журнала.
