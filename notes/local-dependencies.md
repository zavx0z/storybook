# Локальные зависимости без установленных копий

Публичные импорты локальных пакетов ведут в их исходные каталоги.
Изменение файла видно при следующем чтении без повторного копирования пакета
в `node_modules`. Имя пакета и его `exports` сохраняют границу импорта.

## Как подключены пакеты

В [корневом package.json](../package.json) пакеты текущего workspace используют
`workspace:*`, а внешние пакеты Immersive и Highlighter — обычные диапазоны
версий с `^`. Корневой `overrides` выбирает их локальные разрешения
`link:<имя-пакета>`; Bun формирует lockfile и использует зарегистрированные
исходные каталоги. Соседние репозитории
не добавляются в поле `workspaces`, определяющее состав Storybook, и не становятся
его дочерними пакетами в навигации.

[Читатель сценариев](../specs/scenarios/reader/package.json) владеет полным отчётом
Bun Test и зависимостью `fast-xml-parser`. Руководства Specs и подготовка пакетных
ревизий используют его публичный API через `workspace:*`; Web получает тот же
сохранённый результат. REST раскрывает исходный код сценариев без их исполнения.
Highlighter имеет один источник для Storybook и UI.

`link:<имя>` использует общую регистрацию Bun. Перед регистрацией проверяется
её текущая цель: одноимённую ссылку другого проекта нельзя молча перепривязать.
Переименование каталога требует обновить регистрацию Bun. Переименование пакета
учитывается по его актуальному `package.json`, без сохранения прежнего имени
как псевдонима.

## Установка

Порядок регистрации пакетов и выбора локальных источников раскрыт
в [руководстве команд](../app/notes/commands.md#установка-локальных-зависимостей).
Установкой workspace владеет корневой Repo и его `bun.lock`.
`bun install --frozen-lockfile` из вложенного MCP также использует эту установку.
Смена способа подключения локального пакета сама по себе не требует обновлять
версии сторонних библиотек.

Проверка [идентичности пакетов](../tests/package-identity.test.ts) сверяет
символические ссылки и реальные пути публичных импортов, в том числе App
из REST. Это выявляет старую вложенную копию в `node_modules`, которая может
перекрывать правильную ссылку выше по дереву.

## Что ссылка не обновляет

Ссылка не сбрасывает кэш уже загруженных модулей и не заменяет сборку пакета,
если его публичный вход указывает на `dist`. Применение новой сборки Storybook
остаётся отдельным действием через его MCP. Повторный запуск сценария читает
актуальные исходники; изменение данных HTTP-ответа не требует менять контракт
MCP-прокси.
