# Как пакет и его исходники представлены в Storybook

Целевая структура определяется [стандартом Archetypes](./draft-structure.md).
Классификация пакета получается из нормативных сценариев, а не из признаков
обычной директории. При этом действующий Storybook ещё показывает директории
переходных пакетов. Ниже описан этот механизм, чтобы его не принимать за
дополнительные классы Entity или Category.

## Единый каталог

[Обнаружение](../../package/metadata/collect/index.ts) передаёт пакеты, TSDoc, контракты и spec
в [нормализованный каталог](../../package/metadata/collect/contract/catalog.ts).
[Граф](../graph/create/index.ts), UI и [проекция MCP](../../app/server/src/mcp-entries.ts) используют
эти данные. В текущем каталоге публичные директории также могут иметь адреса
MCP. Утверждение «MCP адресует только пакеты» больше не описывает реализацию.

Идентичность пакета определяется его metadata. Название обычной директории
берётся с диска. Один адресуемый предмет может иметь несколько представлений;
вкладка, вариант сценария и пакет не являются взаимозаменяемыми понятиями.
Новые классы не требуют второй декларации навигации или отдельного графа MCP.

## Обход переходных директорий

[Читатель директорий](../../package/metadata/collect/src/directories.ts) использует
[общие правила Route](../route/directories/index.ts).
Наличие допустимого `index.tsx` или собственного `src/` останавливает рекурсивный
обход на модуле. Один `index.ts` промежуточной директории сам по себе обход
не останавливает. Этот механизм сохранён для переходных пакетов и не подтверждает
класс Component. Содержимое exports не используется для построения этого меню.

`src`, `contract`, `spec`, `fixture`, test-директории и директории с
начальной точкой не становятся публичными сегментами маршрута. Остальные
исключения задаёт Git через `git check-ignore --no-index`, включая вложенные
`.gitignore`, правила `!` и уже отслеживаемые Git каталоги. Имена `build` и `dist`
сами по себе не означают исключение. Symlink-директории не обходятся; пустые
обычные директории сохраняются. Директория с package.json не обходится как
обычная: состав самостоятельных пакетов раскрывается через workspaces.

## Обзоры и источники

Обзор берётся из начального TSDoc с `@packageDocumentation` у `index.tsx`,
а при отсутствии допустимого такого файла — у `index.ts`. Git-игнорируемые
файлы и symlink не выбираются. При наличии обоих файлов `index.tsx` имеет
приоритет даже без TSDoc; описания не объединяются. Корень пакета использует
тот же принцип. Отсутствие описания видно явно; README не подставляется.

Это политика discovery. Отдельный
[читатель обзора для readPackage](../reader/src/root-documentation.ts)
пока выбирает обычный index.tsx/index.ts без проверки Git-ignore. При игнорируемом
входе его выбор может отличаться от discovery; единообразие двух путей чтения
остаётся разрывом реализации, а не подтверждённым свойством.

TypeScript при чтении обзора не исполняется. Markdown, блоки кода, @remarks и
@example сохраняются; документация отдельных функций не подменяет обзор.
Текст публикуется как module.md после проверки digest исходника. Локальные
ресурсы разрешаются относительно выбранного входа через Markdown allow-list.
Контракты, dependency spec и сценарии относятся к их фактическому владельцу.
Доменный путь экспорта не переносит к домену владение реализацией компонента.

## Адреса и обновление

Публичный pathname следует физическому корню и видимым директориям. Внутренние
`dir-` идентификаторы не являются публичными URL. Встроенное представление
выбирается UI-параметром `view`; правила принадлежат
[Route](../route/README.md) и [контракту вкладок](../../app/web/page/shell/workbench/notes/workspace.md#tabs-routes).
MCP получает точный адрес из предыдущего children, без query и fragment.
Публичный путь импорта из exports не заменяет URL страницы.

Изменение файлов само не запускает обновление каталога или сборку. Явная
проверка перечитывает исходники и готовит кандидата; страницы получают новую
ревизию только после успешного применения. Неуспех сохраняет рабочую ревизию.
Каждый вложенный пакет имеет собственные ревизии и диагностику. Навигация
использует тот же Root; второй Document или Canvas ради представления не создаётся.

Отчёт структурного сценария Repo или прежнего Domain-фасада может не иметь
preview. Фиктивный Component для такого представления не требуется.
Это свойство отчёта, а не требование отсутствия поведения у нового Domain
или отсутствия общего протокола у Cluster.
Политика предупреждений и технических ошибок описана
[у сборки](../../app/web/build/notes/compilation.md).

Средовые документы Domain и общий протокол Cluster ещё требуют
[обновления фактов и интеграций](./archetype-transition.md).
Текущая проекция не подтверждает их доступность через UI или MCP.
