# Переходное хранение данных владельцев

Package владеет сбором, записью и чтением собственных сведений независимо от
серверного процесса и дерева Project. `package/metadata/collect` соединяет
существующие читатели и сохраняет общий анализ контрактов. `package/metadata`
предоставляет выбранному пакету чтение, сохранение и обновление данных;
при обновлении поддерева каждый вложенный пакет сохраняется у своего владельца.
Те же операции используют серверные обновления, без отдельного формата данных.
Полученные сведения складываются в `meta/data` соответствующего пакета. Его scope сохраняется целиком
в неизменяемом `catalog.<hash>.json`; `catalog.json` указывает на последнюю запись.
Project хранит `meta/data/tree.json` со структурой, индексами и относительными
ссылками на конкретные документы владельцев. Полные описания, схемы и сценарии
в дереве не дублируются. Граф и descriptor раскрываются прежними средствами
из сохранённых сведений выбранного владельца.

Server открывает это дерево с ФС и обращается к Package за данными владельца.
Композиция и публикация дерева пока остаются в `app/server/catalog`;
его перенос к Project не входит в перенос метаданных Package.
При наличии данных запуск не повторяет discovery
и TypeScript-анализ. Прежний формат metadata переводится без перечитывания исходников;
отсутствие сохранённого дерева запускает первичный сбор. Последующие изменения
исходников подготавливаются только по явному обновлению. Сначала записываются
документы владельцев, затем атомарно публикуется дерево. Старые документы сохраняются
для текущих чтений и отката; ошибка чтения не подменяется данными из памяти.

В памяти процесса остаются рабочие сессии и применённые ревизии. Полный каталог
после открытия Project не удерживается. Слабые ссылки переиспользуют уже прочитанную
версию, не препятствуя освобождению памяти; обращение проверяет файл дерева.
MCP раскрывает сведения выбранного узла, не подготавливая схемы всех владельцев.

Сохранённые сведения Package раскрываются для MCP через `package/mcp-source`.
Сервер передаёт файловый снимок и чтение нормативного типа; он не подбирает
описания и схемы самостоятельно. Repo, Component, Container, Cluster и Domain
формируют ответы в собственных `mcp`, используя общие пакетные читатели
навигации и содержимого. `app/knowledge` разрешает адрес и выбирает владельца по
подтверждённому типу. HTTP-инспекция и адресный чат используют этот же читатель.

Исполнимые инструменты адресного агента также составляются у предметных владельцев.
`package/mcp/tools` связывает общие файловые операции с назначенной областью.
Каждый предметный MCP предоставляет `tools` и может добавить собственные операции;
Repo добавляет статус своего Git-корня. Дубли имён при композиции отклоняются.
`app/environment/tools` выбирает владельца по подтверждённому типу; этот существующий
исполнитель не зависит от MCP SDK и используется окружением напрямую.
Адресного MCP-процесса и его HTTP-обёрток больше нет: внутренний чат и внешний
клиент обращаются к общему `/api/environment`. Неизвестный тип получает общую основу
Package; Project использует её в своей области. Сервер сохраняет назначение и
доставляет обращения, но не собирает предметный набор самостоятельно.
Реализации AI и их публичные описания импортируются напрямую, без AI HTTP.
Рабочая директория закрепляется хостом за подключением и не является аргументом
агента. Чтение соседних правил через среду не даёт файловых прав на их директории.

Беседы располагаются в `meta/chat` физического владельца, корневая беседа —
в `meta/chat` Project. Формат данных и истории пока сохраняется, включая имеющиеся
пути источников и контекст ACP. Прежний общий каталог историй служит источником
миграции и сохраняется для восстановления. Новые записи идут к владельцу.

Заметки размещаются в `meta/notes` соответствующего пакета-владельца.

`meta` содержит данные рабочей среды, истории и заметки и не является исходным пакетом или публичной
ветвью навигации. Обход директорий и workspaces не включает её содержимое в сбор
пакетов и документации. `meta/data`, включая дерево Project, исключается из Git
правилом `**/meta/data/` в каждом Repo и Project. `meta/chat` и `meta/notes` остаются доступными Git.
