# Переход Storybook на структуру

Поручение Владимира от 24 сентября 2026: полностью удалить проектные
декларации Storybook, их каталоги, runtime-адаптеры и директории `.storybook`.
Этот документ фиксирует объём выполненных изменений и свидетельства проверки.

## Граница

- Пакеты определяются package.json и workspaces.
- Дерево содержит пакеты и реальные публичные директории.
- Назначение и поведение принадлежат TSDoc кода, контрактам, сценариям и их
  результатам; README указывает на владельца и ещё не перенесённые заметки.
- Исполнение примеров принадлежит существующему структурному механизму сценариев.
- Оболочка Storybook владеет встроенными инспекторами и общей темой.
- Проектные декларации удалены без нового файла конфигурации или совместимого
  запасного механизма.
- Служебная домашняя `.storybook` с реестром подключённых путей и состоянием
  работающего сервера не является декларацией проекта и сохраняется.

## Аудит перед изменением

До перехода часть тестов импортировала fixtures из служебных проектных
директорий. Проверки поведения компонентов переведены на обычные локальные
fixtures, а проверки удалённого способа описания проекта убраны.
Структурное обнаружение пакетов, директорий, контрактов и сценариев уже
существовало и стало основой общего графа.

## Выполнение

1. Структурное обнаружение пакетов и публичных директорий стало источником графа.
2. Декларации потребителей удалены; поведенческие тесты получили локальные fixtures.
3. Правила и документация обновлены; структурная ревизия проверена и применена
   через MCP.

## Результат исходников

Удалены проектные `.storybook`, их reader и схема, а также ветви исполнения,
существовавшие только для снятого способа описания проекта.
Физические пакеты и директории используют один граф для UI и MCP.
Discovery и Route раскрывают workspaces через общий `@storybook/route/workspaces`.
Сценарии, контракты и документация сохраняют своих структурных владельцев.

Во всех четырёх канонических репозиториях удалены отслеживаемые проектные
`.storybook`. Поведенческие тесты потребителей используют обычные локальные
фикстуры. Домашнее состояние сервера и игнорируемые архивные/сгенерированные
копии внутри `projects`, `.codex`, `dist` и `node_modules` не изменялись.

## Свидетельства проверки

Первый общий прогон Storybook: 630 pass, 7 skip, 34 fail. Ошибки старых тестовых
заготовок и ожиданий исправлены; затронутые проверки повторно прошли. Отдельно
прошли проверки типов, маршрутов, MCP, Archetypes, браузерного lifecycle,
обнаружения и жизненного цикла сессий. Интеграционный тест подтвердил независимость
ревизий A/B/C, сохранение последней рабочей ревизии и восстановление после ошибки.
Проверки применения и отката сценариев сохраняют один Browser Root.

В потребителях прошли целевые поведенческие проверки компонентов и проверки типов.
После дополнительной сверки исправлены все 12 ошибок архитектурного набора WebXR:
устаревшие ожидаемые описания, проверка последовательных групп Bun tests,
состав workspaces и учёт изменений публичных типов. Повторный
`bun run test:architecture` завершился с 46 pass и 0 fail.
Реализация платформы не менялась. В тестовой заготовке Layout удалён ненужный
`Worker.unref`; завершение Worker остаётся в `dispose()` из `finally`.

Через свежее Storybook MCP подключение проверены и применены:
- `@zavx0z/storybook`: ревизия `32e02c25bee1d70321541ab6`, реальное дерево
  просмотрено на снимке; диагностика и консоль пусты.
- `@archetypes/package`: ревизия `b7db6d1bc5c3b9e45456be24`, структурный
  сценарий показал «Проверки пройдены», ревизия подтверждена как `active`.

После перезапуска подключения в настройках приложения проверен именно встроенный
`storybook_status` текущей сессии: `status: success`, сервер работает,
ошибки обнаружения и диагностика пакета отсутствуют. Необходимость
переподключения закрыта; отдельный временный клиент для этой проверки не использовался.

## Сверка заметок 25 сентября

В документах оставались инструкции снятого контракта и противоречивое правило
о README как источнике смысла. Они удалены; опорные решения —
[манифест](../MANIFEST.md) и [жизненный цикл заметок](../archetypes/notes/note-lifecycle.md).
Markdown и TSDoc исправлены без изменения исполняемого поведения.

## Устранение кодовых расхождений

Чтение README удалено из результата `readPackage`, каталога, ресурсов ревизии
и интерфейса. Корень пакета использует тот же TSDoc reader, что директории.
`label` в читателе метаданных необязателен, а поисковая схема допускает только
виды текущего графа. Результат читателя пакета — `packageJson`, `documentation`
и `index`; новый формат раскрытия содержимого через публичный MCP пока не вводится.

Источники норм остаются у Archetypes и владельцев соответствующих контрактов.
