# Repo как пакет-монорепозиторий

Repo — корневой пакет самостоятельного Git-репозитория. Его вложенные пакеты
сохраняют идентичность, контракты и зависимости в общей границе версионирования.
Project объединяет независимые Repo ссылками; вложенные самостоятельные Repo
не входят в согласованную модель. Один Repo может участвовать в нескольких Project.

[readRepo](../../index.ts) сопоставляет путь пакета с корнем Git, проверяет gitlinks
и маркеры Git у обнаруженных вложенных пакетов. Это фактический охват читателя,
а не полный поиск произвольных неучтённых директорий на диске.
[Нормативный сценарий Package](../../../../package/reader/spec/scenario.spec.ts) использует эти сведения для
проверки границы Repo. Общие требования пакета принадлежат
[Package](../../../../package/reader/index.ts).

## Единственный workspace

Workspaces объявляет только Repo. Корневые glob охватывают рабочие пакеты без
ручного перечня. Domain, Component и
[Container](../../../../container/src/architecture.md) не повторяют декларацию: их состав
выводится
из общего списка и ближайшего физического пакета-владельца.

Используется штатная установка Bun, без генератора списка и собственных symlink
скриптов. Положительные шаблоны не пересекаются; исключения убирают tests, fixtures,
node_modules и служебные каталоги. Иначе script может выполниться повторно или
тестовый пакет попасть в рабочую установку. Сам домен также должен попадать под
glob вида domain/**. Состав читателя сверяется с фактическим составом Bun.

Вложенная команда установки использует тот же workspace и lockfile. Переход
через границу другого Git Repo запрещён. Фикстура независимого репозитория может
иметь собственную корневую декларацию, но не входит в workspace проверяющего Repo.
