# Структурные маршруты

`@storybook/route` связывает адрес с текущей публичной структурой явно
зарегистрированного пакета. Путь раскрывается только по непосредственной ветке:
вложенные пакеты принадлежат `workspaces`, а категории и сущности — фактическим
видимым директориям. `package.json#exports` определяет API пакета независимо и
не классифицирует узлы маршрута.

Resolver читает только метаданные файловой структуры. Он не загружает модули,
не запускает спецификации и не сохраняет предварительно построенное дерево.
Поэтому следующий вызов видит уже применённое изменение структуры пакета.
Видимость остальных директорий проверяется native `git check-ignore`; `src`,
`shared`, `spec`, `fixture`, служебные test-директории, dot-directories и symlink
не становятся сегментами. Директория с `package.json` доступна только через
workspace composition.

Если structural branch не существует, resolver проверяет exact category,
subject или executable variant route в актуальном package-owned каталоге из
`.storybook/manifest.json`. Этот совместимый authored presentation остаётся
leaf и не создаёт вторую карту адресов или обход всего дерева для списка детей.

Внутренние директории, символические ссылки и выход за зарегистрированный корень
не образуют адрес. Pathname обозначает только сущность. Представления
`scenarios`, `contract` и `dependencies` выбираются query-параметром `view`,
если у непосредственного владельца существуют соответствующие файлы. Отсутствие
параметра и `view=overview` обозначают базовый обзор. Публичная сущность с именем
`scenarios` сохраняет собственный путь и открывает свой сценарий через
`?view=scenarios`.

`index.tsx` или собственная `src` завершают обход на модуле. Обычный `index.ts`
может описывать промежуточную категорию и не скрывает её видимых детей.
