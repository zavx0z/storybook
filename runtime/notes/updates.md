# Динамическое обновление страницы

Обновлением владеет [контроллер страницы](../page-entry.ts). [Исполняемые проверки](../package-entry.test.ts) покрывают замену среды, откат и запросы bridge во время HMR.

## Подготовленная ревизия и HMR

Published package revision immutable; candidate пишет отдельный staging.
Last-good artifact не перезаписывается. Изменение общей оболочки требует
проверки совместимости каждой открытой страницы.

Обычное применение новой package revision выполняется внутри существующей
страницы: URL, browser realm, Root, Document и Canvas сохраняются. Механизм
agent preview не используется для автоматического применения. Новая ревизия
сначала загружает и проверяет свои данные, затем заменяет исполнение пакета
в существующей оболочке. Ошибка подготовки сохраняет прежнее исполнение;
ошибка монтирования восстанавливает предыдущую рабочую привязку.

Общая оболочка принадлежит Storybook и имеет одну опубликованную версию
для всех вкладок. Ревизия потребительского пакета хранит graph, сценарии и
identity платформы, но не выбирает `startPage`, `startPackage` или версию Minimap.
[Bootstrap](../shared-bootstrap.ts) получает серверное описание совместимой
оболочки **до** первого импорта платформы. Переход к старому пакету не возвращает
прежнюю оболочку: [page controller](../page-entry.ts) запрашивает текущую версию
для kernel этого пакета через [shared host](../shared-host.ts).

`shared.updated` приходит всем package/catalog/registry подписчикам, в том числе
при переподключении. Контроллер страницы последовательно применяет новую оболочку
с теми же package revision, маршрутом, query и browser realm. Package build и
применённый стандарт потребителя при этом не меняются. Inspector и вариант сценария
восстанавливаются из адреса; поиск, прокрутка и настройки Inspector передаются
новой оболочке. Завершённая геометрия Minimap, MCP и ViewPoint, раскрытие дерева и настройки
Inspector переносятся снимком именно этой вкладки; запись другой вкладки
в общий localStorage не заменяет её текущее состояние. Произвольное внутреннее состояние заново смонтированного
сценария не объявляется сохранённым без собственного контракта переноса.

При той же платформе и составе author styles передаётся Browser IntegrationRoot.
Его штатный `render` монтирует **новую App**, сохраняя semantic Document и native
Canvas. Старая shell освобождает listeners и представления; её компоненты не
передаются в новый host. При смене kernel освобождается прежний Root, и новая
согласованная модульная среда получает тот же native Canvas. Native Document,
URL и browser realm остаются прежними. Ошибка монтирования восстанавливает
прежнюю оболочку и содержимое; переход не становится успешным из-за готовности
только каталога.

Версия host учитывает исходники интерфейса, компилятор и публичные стили.
Для сохранённых платформ текущий host компилируется отдельно против их exact
kernel imports. Это не пересборка потребительского пакета и не подмена epoch.
Исторические пакеты, для которых прежний формат не сохранил kernel metadata,
не получают выдуманной совместимости: требуется однократная явная миграция их
ревизии. Старые браузерные страницы без shared-update протокола тоже не объявляются
обновлёнными по состоянию новой фоновой вкладки.

## Переходы и запросы во время обновления

Проверки agent bridge ожидают завершения текущей очереди смены package scope.
Промежуток между освобождением старого scope и подключением нового не читается
как рабочая страница. После ожидания expected package проверяется заново;
запрос прежнего пакета не получает права действовать в новом.
Уход пользователя во время применения кандидата откладывает применение,
сохраняя готового кандидата и lastWorking, а не создаёт ошибку сборки пакета.
Следующая явная проверка может применить сохранённого кандидата.
Ошибки монтирования, platform epoch и новые ошибки console сохраняют обычную
проверку и откат. Проверки: runtime/package-entry.test.ts и
server/checked-publication.test.ts.

## Проверки поведения

Publication integration доказывает: явный live-check проходит exact
browser-проверку в существующей package page и обновляет всех читателей
пакета; явный preview сам себя не применяет. Ошибка оставляет lastWorking, исчезнувшая
page не создаёт replacement target, другой package не получает update. Применённая
версия восстанавливается после restart, а потерянное событие — при переподписке.
Проверка обычного обновления сравнивает browser timeOrigin до и после применения,
подтверждает сохранение Root/Canvas и выбранного маршрута; новая ошибка console
не смешивается с историей ошибок предыдущей ревизии. При смене платформы
проверяются передача того же native Canvas новой среде, сохранение browser
timeOrigin и восстановление прежней среды при ошибке монтирования.
Live inspection и capture проверяют exact route, ready/presented и console; это
evidence, а не визуальная приёмка пользователем.
