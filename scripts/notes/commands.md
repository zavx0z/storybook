# Команды инструмента

Команды реализованы в [CLI](../storybook.ts) и используют общий [контроллер](../../server/controller.ts).

Поддерживаются `serve [root...]`, `attach <root>`, `detach <scope-id>`,
`open <package-id> [route]`, `status`, `check <scope-or-path>` и `stop`.
`serve` и `attach` принимают физический корень с `package.json`; workspaces
раскрываются по этому файлу. Команда создания проектных деклараций отсутствует.

## Установка локальных зависимостей

Собственные пакеты Storybook используют `workspace:*`. Внешние пакеты объявлены
в корневом `package.json` обычными диапазонами версий. Корневой `overrides`
выбирает зарегистрированные локальные источники через `link:<имя-пакета>`.
Директории другого репозитория не становятся workspaces Storybook и не
записываются в его манифест.

Перед установкой каждый внешний пакет регистрируется командой `bun link`
из собственного фактического каталога с `package.json`. Регистрация принадлежит
машине; после перемещения каталога её обновляют. Регистрация задаёт фактический
каталог, а `overrides` сохраняет выбор локального источника при установке и
обновлении. Самой регистрации недостаточно, чтобы обычный диапазон версий
перестал обращаться к registry.

`bun install` и `bun update` формируют lockfile штатно по манифесту; ручная
синхронизация деклараций в lockfile не требуется. Для установки сохранённого
набора используется `bun install --frozen-lockfile`. `peerDependencies` задаёт
роль требования к окружению; собственный пакет Repo использует `workspace:*`
и в этой карте, внешний владелец — обычный диапазон совместимости.
Регистрация описана в [документации bun link](https://bun.sh/docs/pm/cli/link),
выбор источников — в [контракте overrides](https://bun.sh/docs/pm/overrides).
