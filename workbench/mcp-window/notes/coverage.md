# Что подтверждают проверки окна

[Сценарий](../spec/scenario.spec.ts) раскрывает состояния и действия настоящего
McpWindow. Фикстура подготавливает данные и изолированную среду; тесты не скрыты
в помощниках. Окно монтируется через публичные Component и DOM, раскладка и
pointer-ввод используют публичный Renderer. Базовые Window и CodeEditor не подменяются.

Полный ответ остаётся в редакторе. Переключаются команды, а не фрагменты ответа;
в DOM одновременно находится одна команда. Выбор старой записи не отменяет
обновление её результата, а отдельная команда возвращает слежение за последней.

Поле documentation остаётся частью JSON и не включает отдельное визуальное
представление. Это проверяется [тестом полного ответа](../test/json-response.test.ts).

[Проверки адресного режима](../test/address.test.ts) проверяют показ только пакетного
адреса из ответа сервера, смену URL во время запроса, ручное обновление и прекращение
чтений при закрытии или смене режима. Сценарий окна показывает оба режима.
HTTP-проверка сервера сравнивает ответы browser-чтения и MCP-адаптера, включая
переходы по внутренним URL, ошибку неизвестного пакета, авторизацию и сохранность журнала агента.

[Восстановление состояния](../test/persistence.test.ts) проверяется переносом
сохранённых настроек в новое окно после перемещения, resize, смены режима,
сворачивания и закрытия. Повреждённое или недоступное хранилище проверяется отдельно.

[Регрессионные тесты](../test/window.test.ts) проверяют переход running в большой
ответ, историю из двадцати записей, смену источника, поздние ответы, ошибки и
восстановление загрузки, cleanup, отмену жестов и границы геометрии. Опрос использует
настоящий таймер компонента: новый запрос начинается после завершения предыдущего.

Эти проверки подтверждают DOM, раскладку, данные и обработку событий. Они не
доказывают отсутствие зависания GPU или вкладки Chrome: для этого по-прежнему
нужна проверка того же сценария в браузере. Завершение теста не заменяет снимок
и проверку отзывчивости окна.
